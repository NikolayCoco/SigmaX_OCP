# 一、`control_example.py` —— 第二个问题（**可替换性的证明**）

## 1.1 为什么需要这个文件

如果整个项目只有量子比特一个问题，那"求解器与问题解耦"就只是一句口号。
`ControlExample` 的作用就是**用事实证明这个设计真的成立**：

| | QubitReset | ControlExample |
|---|---|---|
| 状态维数 | 3 | 1 |
| 控制维数 | 2 | 1 |
| 成本类型 | 终端成本（Mayer）$J=\|p(\tau)\|$ | 运行成本（Lagrange）$J=\int \frac{1}{2}(x^2+u^2)dt$ |
| 约束 | 盒约束 $0\le u\le u_{\max}$ | 无约束 $-\infty<u<\infty$ |
| 协态边界条件 | 终端给定 $\mu(\tau)=-\kappa p/\|p\|$ | 终端自由 $\mu(1)=0$ |

**两者几乎没有任何共同点**，但都实现了同一个 `AbstractOCP` 契约，
所以 `GradientSolver` **一行代码都不用改**。

> 这正是抽象接口的价值所在 —— 也是你在简历/面试里最值得强调的一点。

## 1.2 问题定义

$$
\min\ J = \int_0^1 \frac{1}{2}\left(x^2 + u^2\right)dt
\quad \text{s.t.}\quad x(0)=10,\quad x' = -x^2 + u,\quad x(1)\ \text{自由}
$$

- 这是**经典 LQR 风格的运行成本问题**：既希望状态 $x$ 小（第一项），
  又希望控制 $u$ 不要太大（第二项）。
- 动力学 $x' = -x^2+u$ 是**非线性**的（有 $x^2$ 项），所以必须数值求解。
- 协态方程（由 PMP 推出）：$\lambda' = 2x\lambda + x$，终端条件 $\lambda(1)=0$。
- 梯度（解析）：$\nabla_u J = u - \lambda$。

## 1.3 逐段讲解

```python
class ControlExample(AbstractOCP):
    n_state = 1
    n_control = 1
    name = "descriptor example 1 (x'=-x^2+u)"

    def __init__(self, **kwargs) -> None:
        super().__init__()
        self.N = 200
        self.homotopy_name = ""
        self.set(**kwargs)
```

- `n_state = 1` / `n_control = 1` —— **标量问题**。这本身就说明求解器不依赖具体维数。
- `self.N = 200` —— 默认 200 个采样点（量子比特问题默认是 100）。
- `self.homotopy_name = ""` —— **空串表示"这个问题不支持延拓"**。
  如果被放进 `HomotopyContinuation`，`set_homotopy` 只会存值，不改任何东西。

```python
    def time_grid(self, N=None):
        if N is None:
            N = self.N
        return np.linspace(0.0, self.tau, int(N))
```

- `self.tau` 继承自基类，默认 `1.0`。所以时间区间是 $[0,1]$。

```python
    def initial_state(self):
        return np.array([10.0])

    def initial_control(self, tg):
        return np.zeros((1, tg.size))
```

- **返回 `(1,)` 而不是标量** —— 严格遵守契约里的形状约定
  （`n_state=1` 也要返回长度为 1 的数组）。
  **这一点很重要**：如果返回裸标量 `10.0`，后面 `X[:, 0] = X0` 还能工作，
  但 `X.shape` 的推断可能出错。**统一形状能避免大量偶发 bug。**

- `np.zeros((1, tg.size))` —— 初始控制猜测是全 0。
  **注意是二维 `(1, N)` 而不是一维 `(N,)`** —— 契约要求 `(n_control, N)`。

```python
    def control_bounds(self):
        return np.array([-np.inf]), np.array([np.inf])

    def project(self, U):
        return U
```

- **无约束问题**：上下界是 $\pm\infty$，`project` 是**恒等映射**。
- **对照 `QubitReset`**：那边有真实的盒约束、`project` 用 `np.clip`。
  **同一个求解器，通过 `project` 的多态就同时支持了有约束和无约束问题** ——
  这是"策略模式"的典型应用。

- `np.array([-np.inf])` —— 必须是**数组**，因为求解器的
  `_apply_active_set` 里会做 `lo[:, None]` 升维。返回裸标量会报错。

```python
    def cost_gradient(self, tg, U):
        N = tg.size

        # 前向积分状态（RK4，控制分段常数）
        X = np.zeros(N)
        X[0] = self.initial_state()[0]
        for k in range(N - 1):
            dt = tg[k + 1] - tg[k]
            X[k + 1] = self._rk4(lambda x, u=U[0, k]: self._f(x, u), X[k], dt)
```

**逐行：**

- `X = np.zeros(N)` —— **一维数组**（因为 `n_state=1`）。
  和 `QubitReset` 里的 `(3, N)` 二维不同 —— **这就是"形状随问题变"的体现**。

- `X[0] = self.initial_state()[0]` ——
  `initial_state()` 返回 `(1,)` 数组，`[0]` 取出标量。
  **MATLAB 对照**：`X(1) = obj.initialState();`（MATLAB 里会自动取标量）。

- `for k in range(N - 1):` —— **MATLAB 对照**：`for k = 1:N-1`。

- `lambda x, u=U[0, k]: self._f(x, u)` ——
  把当前采样点的控制值 `u` **绑定**进 lambda，然后 RK4 内部只需传状态 `x`。
  这是"把二元函数化成一元函数"的标准手法。
  **MATLAB 对照**：`@(x) f(x, U(k))`。

```python
        # 后向积分协态（终端自然边界条件 lambda(1) = 0）
        Mu = np.zeros(N)
        Mu[N - 1] = 0.0
        for k in range(N - 1, 0, -1):
            dt = tg[k] - tg[k - 1]
            x_prev = X[k - 1]
            Mu[k - 1] = self._rk4(lambda la, x=x_prev: -self._dlam(x, la), Mu[k], dt)
```

**逐行（注意和 `QubitReset` 的对比）：**

- `Mu[N - 1] = 0.0` —— 终端条件是 **0**，因为终端状态自由
  （**自然边界条件 / 横截条件**：终端无成本，所以协态终值为 0）。
  **对照 `QubitReset`**：那边终端成本是 $|p(\tau)|$，所以
  $\mu(\tau) = -\kappa p(\tau)/|p(\tau)| \ne 0$。

- `for k in range(N - 1, 0, -1):` ——
  **MATLAB 对照**：`for k = N:-1:2`，下标整体 −1。

- `Mu[k - 1] = self._rk4(lambda la, x=x_prev: -self._dlam(x, la), Mu[k], dt)` ——
  **这里有个容易看错的地方**：协态方程的右端是 `-dlam`，**带负号**。

  **为什么？** `_dlam(x, λ) = 2xλ + x` 是**正向时间**的 $\dot\lambda$。
  但我们要**逆着时间**积分，所以右端取负号：
  $\frac{d\lambda}{ds}\big|_{s=-t} = -\dot\lambda$。
  代码里通过 `-self._dlam(...)` 显式表达这个负号 ——
  比 `QubitReset` 里"用 $A^\top$ 但不写负号"的写法**更直观**。

  > 注意 `x_prev = X[k - 1]` 先取出来存成局部变量再绑定进 lambda。
  > 这是**防御性写法**：如果直接在 lambda 里引用 `X[k-1]`，
  > 由于 `k` 是循环变量，一旦 lambda 被延迟调用就会取到错误的 `k`。

```python
        J = AbstractOCP.trapezoid(tg, 0.5 * (X**2 + U[0, :] ** 2))
        G = U - Mu[None, :]

        return J, X[None, :], Mu[None, :], G
```

**逐行：**

- `0.5 * (X**2 + U[0,:]**2)` —— 被积函数 $\frac{1}{2}(x^2+u^2)$。
- `AbstractOCP.trapezoid(tg, ...)` —— 沿时间积分得标量 $J$。

- `G = U - Mu[None, :]` —— **解析梯度** $\nabla_u J = u - \lambda$。
  - `U` 是 `(1, N)`，`Mu` 是 `(N,)`。
  - `Mu[None, :]` 把 `(N,)` 变成 `(1, N)`，才能和 `(1,N)` 的 `U` 相减。
    **MATLAB 里不需要这么做**，因为 MATLAB 的 `Mu` 本来就是 `(1,N)` 行向量。
    **这是 numpy 一维数组带来的额外步骤。**

- `X[None, :]` / `Mu[None, :]` —— **把一维状态升成二维**再返回。
  因为契约规定返回 `(n_state, N)`，而这里内部计算用的是一维。
  `[None, :]` 等价于 `np.newaxis`，在位置 0 插入一个新维度。

> **这个细节很值得记住**：`x[None, :]` 把 `(N,)` → `(1, N)`；
> `x[:, None]` 把 `(N,)` → `(N, 1)`。两者方向相反，**用错会导致广播错误**。

```python
    @staticmethod
    def _f(x, u):
        """x' = -x^2 + u"""
        return -x * x + u

    @staticmethod
    def _dlam(x, lam):
        """协态方程右端：lambda' = 2 x lambda + x"""
        return 2.0 * x * lam + x

    @staticmethod
    def _rk4(f, x, dt):
        k1 = f(x)
        k2 = f(x + 0.5 * dt * k1)
        k3 = f(x + 0.5 * dt * k2)
        k4 = f(x + dt * k3)
        return x + (dt / 6.0) * (k1 + 2.0 * k2 + 2.0 * k3 + k4)
```

- `-x * x` 而不是 `-x**2` —— 纯风格选择，等价。
- `_rk4` 与 `QubitReset._rk4` **公式完全相同**，但因为是标量版本，
  所以单独实现（没有共享基类）。
  > **一个可改进点**：这个 RK4 其实可以提到 `AbstractOCP` 里做公共方法
  > （标量/向量都能用）。原项目为了保持与 MATLAB 的逐文件对应关系没有这么做。

# 二、`homotopy_continuation.py` —— 同伦延拓

## 2.1 它解决什么问题

梯度下降是**局部**算法：初值不好就可能卡在高原、鞍点或局部极小。
这个问题的具体症状是：

> 当时间窗口 $\tau$ 较长时，终端成本 $|p(\tau)|$ 对**初始时刻**
> 控制值的梯度会**趋于消失**（初值位置梯度消失）。
> 于是从零猜开始优化，前面一大段控制几乎不动，收敛极慢甚至停滞。

**延拓（continuation / homotopy）的思路**：

```
容易的问题                    逐步变形                    真正要解的问题
  τ = 0.1        ──►     τ = 0.4  ──►  τ = 0.8  ──►  ...  ──►   τ = 1.5
  （梯度不消失）              每一步都用上一步的解做初值（热启动）
```

因为相邻参数的问题解非常接近，**上一步的解就是下一步极好的初值**，
梯度不会消失，收敛顺理成章。

**这个外壳与问题无关** —— 它只调用 `model.set_homotopy()` 和 `GradientSolver`，
所以任何支持延拓的 `AbstractOCP` 都能用。

## 2.2 两个结果容器

```python
@dataclass
class ContinuationStep:
    U: np.ndarray          # 该步求得的控制
    J: float               # 该步的成本
    params: float          # 该步的延拓参数值
    converged: bool        # 该步是否收敛


@dataclass
class ContinuationResult:
    results: list[ContinuationStep]
    path: np.ndarray
    tgrids: list[np.ndarray]
    U: np.ndarray
    J: float
```

- `params` 字段名**故意保持和 MATLAB 一致**
  （MATLAB 里 `results(i).params`），虽然叫 `param_value` 更符合英文习惯。
- `list[ContinuationStep]` —— 泛型注解，说明这是"ContinuationStep 的列表"。

## 2.3 `__init__`：三种构造方式

```python
    def __init__(self, model, path, solver=None, **solver_kwargs) -> None:
        self.model = model
        self.path = np.asarray(path, dtype=float)
        self.verbose = True

        if solver is not None:
            self.solver = solver
        else:
            self.solver = GradientSolver(model, **solver_kwargs)

        self.N: int = int(getattr(model, "N", 100))

        if self.path.size and self.model.homotopy_value != self.path[0]:
            self.model.set_homotopy(float(self.path[0]))
```

**逐行：**

- `self.path = np.asarray(path, dtype=float)` ——
  接受 list / tuple / ndarray，统一转成浮点数组。
  这样 `path[0]`、`path.size`、`path[i]` 都能用。

- **三种构造方式**（对应 MATLAB 的 `varargin` 分派）：

  | 用法 | 行为 |
  |---|---|
  | `HomotopyContinuation(model, path)` | 用模型默认参数新建求解器 |
  | `HomotopyContinuation(model, path, solver=my_solver)` | 直接用传入的求解器 |
  | `HomotopyContinuation(model, path, max_iter=800)` | 用指定参数新建求解器 |

  **MATLAB 对照**：

  ```matlab
  if isempty(varargin)
      obj.solver = solver.GradientSolver(model);
  elseif isa(varargin{1}, 'solver.GradientSolver')
      obj.solver = varargin{1};
  else
      obj.solver = solver.GradientSolver(model, varargin{:});
  end
  ```

  Python 用"可选参数默认 `None`" + `**kwargs` 就把这个分派表达清楚了，
  **不需要运行时类型检查**（`isa` 在 Python 里几乎总是坏味道）。

- `getattr(model, "N", 100)` —— **安全取属性**：
  模型有 `N` 就用，没有就给默认值 100。
  **MATLAB 对照**：`if isprop(model, 'N'), obj.N = model.N; else, obj.N = 100; end`。
  `getattr` 的三参数形式正好对应这个"取属性带默认值"的模式。

- 最后那个 `if`：**保证模型从路径起点开始**。
  **MATLAB 对照**：`if obj.model.homotopyValue ~= path(1), obj.model.setHomotopy(path(1)); end`

## 2.4 `run()`：延拓主循环

```python
    def run(self, U0=None) -> ContinuationResult:
        path = self.path
        nP = path.size
        tg_cache: list[np.ndarray] = []
        results: list[ContinuationStep] = []
        U = U0

        for i in range(nP):
            self.model.set_homotopy(float(path[i]))
            tg = self.model.time_grid(self.N)
            tg_cache.append(tg)

            if U is None:
                U = self.model.initial_control(tg)

            if self.verbose:
                print(f"== prolong step {i + 1}/{nP} : "
                      f"{self.model.homotopy_name} = {path[i]:.4g} ==")

            sol = self.solver.solve(U, tg)
            results.append(ContinuationStep(
                U=sol.U, J=sol.J, params=float(path[i]), converged=sol.converged))
            U = sol.U      # 作为下一步的热启动
```

**逐行（**这四行的顺序非常关键**）：**

1. `self.model.set_homotopy(float(path[i]))` ——
   **先设参数**。对 `'tau'` 族，这一步会改 `model.tau`。

2. `tg = self.model.time_grid(self.N)` ——
   **再重建时间格点**。因为 `tau` 变了，格点必须跟着变。
   ⚠️ **顺序反了就会用旧的时间范围求解** —— 这是延拓实现里最容易搞错的地方。

3. `if U is None: U = self.model.initial_control(tg)` ——
   只在**第一步**生成初始猜测，后面都用热启动。

4. `sol = self.solver.solve(U, tg)` —— 求解。
   **注意这里显式传了 `tg`**，绕开了"求解器用自己的 `N`"那个坑
   （README 7.1 节）。**延拓这里必须显式传**，因为每个 `tau` 对应的格点不同。

5. `U = sol.U` —— **热启动**：把这一步的解作为下一步的初值。
   **这一行就是整个延拓能工作的核心。**

- `print(f"... {i + 1}/{nP} ...")` ——
  `i` 是 0-based，所以显示时 `+1` 转回人类习惯的 1-based。
  **MATLAB 对照**：`fprintf('== prolong step %d/%d ...', i, nP, ...)`
  （MATLAB 的 `i` 本来就是 1-based）。

- `float(path[i])` —— 转成原生 float，
  避免把 `np.float64` 存进 dataclass 后序列化或格式化时出意外。

```python
        return ContinuationResult(
            results=results, path=path, tgrids=tg_cache,
            U=results[-1].U, J=results[-1].J,
        )
```

- `results[-1]` —— **最后一步**的解就是最终答案。
  **MATLAB 对照**：`results(end).U`。

> **一个设计细节**：`tg_cache` 保存了每一步的时间格点，
> 因为不同步的 `tau` 不同、格点长度也可能不同。
> 如果拿最终的 `tg` 去画中间某一步的控制，维度会对不上。

# 三、`visualizer.py` —— 可视化与动画

## 3.1 它的工作方式：观察者模式

梯度求解器有个 `observer` 回调，每轮迭代调用一次：

```python
s.observer = lambda it, J, X, Mu, U, tg: v.snapshot(it, J, X, Mu, U, tg)
```

**这是"观察者模式"**：求解器**完全不知道**可视化器的存在，
它只是在每轮"广播"一次当前状态。好处是：

- 求解器代码里**没有任何绘图逻辑**（关注点分离）
- 你可以挂任意回调：画图、记日志、存 CSV、早停……
- 设为 `None` 时**零开销**（一次 `is not None` 判断）

**MATLAB 对照**：`s.observer = @(iter,J,X,Mu,U,tg) v.snapshot(...);`
Python 用 `lambda`，语义完全一样。

## 3.2 与 MATLAB 的关键差异：后端

```python
def __init__(self, animate=False, format="gif", video_file="iteration.gif",
             fps=12, show_live=False, xlabel="time"):
```

**两个有意的差异：**

| 项 | MATLAB 默认 | Python 默认 | 原因 |
|---|---|---|---|
| `show_live` / `showLive` | `true` | **`False`** | Python 常在无图形界面的环境跑（服务器、CI、自动化脚本），弹窗会卡住或报错 |
| 渲染后端 | MATLAB 自带 | **纯 Agg**（`FigureCanvasAgg`） | 不依赖 GUI，也能导出 GIF |

```python
        from matplotlib.backends.backend_agg import FigureCanvasAgg
        from matplotlib.figure import Figure

        self._fig = Figure(figsize=(12.0, 8.0), dpi=100, facecolor="white")
        self._canvas = FigureCanvasAgg(self._fig)
```

- **注意：这里没有用 `pyplot`**，而是直接构造 `Figure` + `FigureCanvasAgg`。
  **为什么？** `pyplot` 是个全局状态机，导入时就可能选定一个 GUI 后端
  （TkAgg/QtAgg），在没有显示器的机器上会失败。直接用 `Figure` 对象是
  **"无头（headless）渲染"** 的标准做法，任何环境都能跑。

- `figsize=(12.0, 8.0)` —— 12×8 英寸，对应 MATLAB 的 `Position [60 60 1200 800]`
  （像素，按 100 dpi 换算）。
- `facecolor="white"` —— **MATLAB 对照**：`figure('Color','w')`。

```python
        self._ax = [self._fig.add_subplot(2, 2, p + 1) for p in range(4)]
        for ax in self._ax:
            ax.grid(True)
```

- **列表推导式**一次建 4 个子图，比写 4 遍清爽。
- `add_subplot(2, 2, p + 1)` —— 2×2 网格里的第 `p+1` 个（1-based，matplotlib 沿用 MATLAB 习惯）。
  **MATLAB 对照**：`subplot(2, 2, p)`。

```python
        if self.show_live:
            import matplotlib.pyplot as plt
            self._plt = plt
            plt.ion()
            plt.show(block=False)
```

- **`import` 放在 `if` 里面**（延迟导入）：只有真的要现场图窗时才导入 `pyplot`。
  这样默认路径（`show_live=False`）**完全不碰 GUI 依赖**。

## 3.3 `snapshot()`：每轮迭代干什么

```python
    def snapshot(self, iter, J, X, Mu, U, tg) -> None:
        self._jhist.append(float(J))
        self._draw_panels(iter, J, X, Mu, U, tg)
        if self.animate:
            self._canvas.draw()
            buf = np.asarray(self._canvas.buffer_rgba())
            self._frames.append(buf[:, :, :3].copy())
        if self.show_live and self._plt is not None:
            self._plt.pause(0.001)
```

**逐行：**

- `self._jhist.append(float(J))` —— 累积成本历史，用于第四个面板。

- `self._canvas.draw()` —— **强制立即渲染**。
  Agg 后端不会自动刷新，必须显式调用。

- `buf = np.asarray(self._canvas.buffer_rgba())` ——
  把画布取成 numpy 数组，形状 `(H, W, 4)`（RGBA 四个通道）。

- `buf[:, :, :3]` —— **丢掉 alpha 通道**，只留 RGB，变成 `(H, W, 3)`。
  GIF 不支持 alpha（严格说支持透明色索引，但 Pillow 保存更省事）。

- **`.copy()` 是必须的！** ⚠️
  `buffer_rgba()` 返回的是一个**视图**，底层缓冲区在下一次 `draw()` 时
  会被**覆盖**。不拷贝的话，你最后会得到 N 张一模一样的"最后一帧"。

  > 这是 matplotlib 动画录制最经典的 bug。**凡是"从渲染器取帧"的场合，
  > 一律要 `.copy()`。**

- `self._plt.pause(0.001)` —— 现场模式下让 GUI 事件循环有机会处理，
  否则窗口会卡死显示"无响应"。

## 3.4 `_write_gif()`：用 Pillow 写 GIF

```python
    def _write_gif(self) -> None:
        from PIL import Image

        images = [Image.fromarray(f) for f in self._frames]
        duration_ms = int(round(1000.0 / max(self.fps, 1)))
        images[0].save(
            self.video_file,
            save_all=True,
            append_images=images[1:],
            duration=duration_ms,
            loop=0,
        )
```

**逐行：**

- `Image.fromarray(f)` —— numpy 数组 → PIL 图像对象。
- `duration_ms = 1000 / fps` —— 每帧显示毫秒数。`max(self.fps, 1)` 防除零。
- `images[0].save(..., save_all=True, append_images=images[1:], ...)` ——
  **Pillow 写多帧 GIF 的固定写法**：
  用第一帧调 `save`，把其余帧通过 `append_images` 传进去。
- `loop=0` —— **无限循环**。`0` 在 Pillow 里表示"永远循环"。
  **MATLAB 对照**：`imwrite(..., 'LoopCount', inf)`。

> **对照 MATLAB 的做法**：MATLAB 是每帧 `rgb2ind` 量化成 256 色调色板，
> 然后逐帧 `imwrite(..., 'WriteMode', 'append')`。
> Pillow 把这一切都封装在 `save` 里了 —— **Python 版代码短得多，
> 这是生态带来的实际收益**。

## 3.5 `_write_mp4()`：没有内置等价物

```python
        if shutil.which("ffmpeg") is None:
            raise RuntimeError(
                "导出 MP4 需要系统里有 ffmpeg 可执行文件。\n"
                "  方案 A：安装 ffmpeg（例如 winget install Gyan.FFmpeg）\n"
                "  方案 B：把 format 改成 'gif'（无需外部依赖）"
            )
```

- **MATLAB 有内置的 `VideoWriter(..., 'MPEG-4')`，Python 没有** ——
  必须依赖外部 `ffmpeg` 可执行文件。
- `shutil.which("ffmpeg")` —— 在 PATH 里查找可执行文件。
- **报错信息里直接给出两条可行方案** —— 这是好错误信息的标准：
  **不要只说"失败了"，要告诉对方怎么解决**。

```python
        with tempfile.TemporaryDirectory() as td:
            for i, f in enumerate(self._frames):
                Image.fromarray(f).save(os.path.join(td, f"f{i:05d}.png"))
            cmd = ["ffmpeg", "-y", "-framerate", str(self.fps),
                   "-i", os.path.join(td, "f%05d.png"),
                   "-c:v", "libx264", "-pix_fmt", "yuv420p",
                   "-vf", "pad=ceil(iw/2)*2:ceil(ih/2)*2",
                   self.video_file]
            subprocess.run(cmd, check=True, capture_output=True)
```

- `tempfile.TemporaryDirectory()` 作为**上下文管理器**：退出时自动删临时目录。
- `f"f{i:05d}.png"` —— 补零到 5 位（`f00000.png`），
  ffmpeg 的 `%05d` 序列模式要求文件名连续编号。
- `-pix_fmt yuv420p` —— H.264 在多数播放器里要求的像素格式。
- `-vf "pad=ceil(iw/2)*2:ceil(ih/2)*2"` ——
  **把画面尺寸补成偶数**。H.264 要求宽高是偶数，
  否则报 `height not divisible by 2`。这是个很常见的坑。
- `subprocess.run(cmd, check=True, capture_output=True)` ——
  `check=True` 表示非零退出码抛异常；`capture_output` 把输出收起来不刷屏。

## 3.6 `_draw_panels()`：四个面板

```python
        n_hist = len(self._jhist)
        idx = np.arange(1, min(n_hist, 400) + 1)
        jvals = np.asarray(self._jhist[: idx.size], dtype=float)
```

- **MATLAB 对照**：`if numel(obj.Jhist) > 400, idx = 1:400; else, idx = 1:numel(obj.Jhist); end`
- Python 用 `min(n_hist, 400)` 一行表达，`np.arange(1, k+1)` 生成 `1..k`。
- **为什么要限制 400**？因为迭代上万次时全画出来又慢又乱，
  只显示前 400 个点足够看出趋势。

```python
        safe = np.maximum(jvals, np.finfo(float).tiny)
        ax.semilogy(idx, safe, "k-", linewidth=1.5)
```

- ⚠️ **`np.finfo(float).tiny` 是"最小的正规格化浮点数"**（约 $2.2\times10^{-308}$）。
- **为什么需要它**？因为纵轴是**对数轴**（`semilogy`），
  如果成本里出现 0 或负数，对数轴会报警告或者画不出来。
  用一个极小正数夹住，既避免报错，视觉上也等价于"0"。

```python
        lo, hi = float(safe.min()), float(safe.max())
        if lo < hi:
            ax.set_ylim(lo * 0.9, hi * 1.1)
```

- **MATLAB 对照**：`ylim(obj.ax(4), [min(obj.Jhist)*0.9, max(obj.Jhist)*1.1]);`
- `if lo < hi:` —— 加了个保护：如果所有值相同（比如只有一帧），
  上下限相同会导致 matplotlib 报错。

```python
        for i in range(ns):
            ax.plot(tg, X[i, :], linewidth=1.5, label=f"p_{i + 1}")
```

- **曲线数量自适应**：`ns = X.shape[0]`，有几维状态就画几条。
  **这就是同一个可视化器能同时服务 3 维量子问题和 1 维标量问题的原因**。
  **MATLAB 对照**：`for i = 1:ns ... legend(obj.names('p', ns))`。

## 4.1 共同的头部：让脚本能直接运行

```python
import pathlib
import sys

sys.path.insert(0, str(pathlib.Path(__file__).resolve().parents[1]))
```

**这四行是每个 demo 都有的，务必理解：**

- **MATLAB 对照**：

  ```matlab
  addpath(fullfile(fileparts(mfilename('fullpath')), '..', 'src'));
  ```

  MATLAB 用 `addpath` 把 `src` 目录加进搜索路径；Python 用 `sys.path.insert`。

- `pathlib.Path(__file__)` —— `__file__` 是当前脚本的路径，
  包成 `Path` 对象后可以方便地做路径运算。
- `.resolve()` —— 转成绝对路径（消掉 `..`、符号链接）。
- `.parents[1]` —— **上一级目录的上一级**，即项目根目录。
  （`.parents[0]` 是 `demo/`，`.parents[1]` 是 `SigmaX_OCP_py/`。）
- `str(...)` —— `sys.path` 只接受字符串。
- `insert(0, ...)` —— 插到**最前面**，确保优先于其他同名包。

> **为什么不用相对导入？** 因为 demo 是**直接运行的脚本**（`python demo/demo_gradient.py`），
> 不是被 import 的模块。直接运行时 Python 不会把项目根目录加进 `sys.path`，
> 所以必须手动加。这是 Python 脚本组织的一个常见痛点。
>
> **更"正规"的做法**是做一个可安装的包（`pyproject.toml` + `pip install -e .`），
> 但对一个教学项目来说，这四行更直接、零配置。

## 4.3 `demo_gradient.py` 的骨架

```python
def main() -> None:
    model = ocp.QubitReset(tau=0.15, N=100, gamma=10, omega_c=1, lambda_max=[3, 2])

    s = solver.GradientSolver(model)
    s.direction = "adam"
    s.line_search = "armijo"
    s.max_iter = 2000
    s.tol_grad = 1e-5
    s.verbosity = 1

    print(f"\n===== solving {model.name} with {s.direction} =====")
    tg = model.time_grid(model.N)
    t0 = time.time()
    res = s.solve(tg=tg)      # 显式传 tg
    elapsed = time.time() - t0
```

- `main()` 函数 + `if __name__ == "__main__": main()` ——
  **Python 的标准脚本结构**。
  - `__name__` 是模块名：直接运行脚本时它是 `"__main__"`；
    被 import 时它是模块名。
  - 所以这个 `if` 保证"**直接运行时执行，被 import 时不执行**"。
  - **好处**：别人可以 `from demo_gradient import main` 来复用，
    而不会意外触发求解。

- `t0 = time.time()` / `time.time() - t0` ——
  **MATLAB 对照**：`t0 = tic; toc(t0)`。
  （追求更高精度可以用 `time.perf_counter()`。）

- `res = s.solve(tg=tg)` —— ⚠️ **显式传 `tg`**。
  这是本项目对 MATLAB 版缺陷的修正（README 7.1 节）。
  `model.N=100` 和 `solver.N=100` 恰好相等时看不出问题，
  但一旦不等就会维度错配，所以**统一显式传**是最安全的习惯。

## 4.5 `demo_animation.py` 的关键接线

```python
    v = vis.Visualizer(animate=True, format="gif",
                       video_file=str(OUT / "iteration.gif"), fps=12, show_live=False)
    tg = model.time_grid(model.N)
    v.init(model, tg)
    s.observer = lambda it, J, X, Mu, U, tgrid: v.snapshot(it, J, X, Mu, U, tgrid)

    res = s.solve(tg=tg)
    v.finish()
```

**三步接线，是理解"观察者模式"的最好例子：**

3. `v.finish()` —— **必须调用**！它负责把攒下的帧写成 GIF。

- `str(OUT / "iteration.gif")` —— `pathlib` 的 `/` 运算符做路径拼接，
  跨平台安全。比 `os.path.join` 更易读。

# 五、`tests/validate_suite.py` —— 自检

## 5.1 为什么自检脚本这么重要

重写一个数值项目，"能跑起来"和"算得对"是**两回事**。
一个符号写反、一个轴搞错，代码照样跑、照样输出数字，但结果是错的。

自检脚本的作用：**把"正确性"变成一条可以随时执行、非黑即白的命令。**

```python
def main() -> int:
    ...
    allok = all([ok1, ok1b, ok2a, ok2b, ok3, ok4])
    print(f"=== done {'(all PASS)' if allok else '(there are FAILures)'} ===")
    return 0 if allok else 1


if __name__ == "__main__":
    raise SystemExit(main())
```

- `all([...])` —— 全部为真才返回 `True`。
- **返回退出码**：0 表示成功，1 表示有失败。
  `raise SystemExit(code)` 把它作为进程退出码。
  **意义**：可以被 CI / 自动化脚本直接使用
  （`if (python validate_suite.py) { ... }`）。

  **MATLAB 对照**：MATLAB 的 `validate_suite` 只是打印，不返回退出码 ——
  Python 版在这里做得更好，体现了"脚本要用退出码表达成败"的工程惯例。

## 5.2 四个检查项

```python
def descent_check(m, tg, U) -> bool:
    """检查解析梯度是不是下降方向（走一小步，成本应当下降）。"""
    J0, _, _, G = m.cost_gradient(tg, U)
    U2 = m.project(U - 1e-3 * G)
    J2, _, _, _ = m.cost_gradient(tg, U2)
    return bool(np.isfinite(J2) and J2 < J0)
```

**这是整个自检里最有价值的 4 行。** 逻辑：

1. 算出当前成本 $J_0$ 和梯度 $G$
2. 沿**负梯度**走一小步（步长 $10^{-3}$），并投影回可行域
3. 再算成本 $J_2$
4. **要求 $J_2 < J_0$**

**为什么这个检验这么关键？** 它能一次性抓住：

- **梯度符号写反**（走反方向成本会上升）→ 最致命的错误
- **梯度的某个分量算错**（比如某个物理函数的偏导转录错了）
- **维度/轴搞错**（虽然不报错，但数值会错到成本不降）
- **投影实现错误**

而且它**不依赖任何参考数值**，是纯粹的"内禀正确性"检验。
**任何梯度类项目都应该有这么一个测试。**

```python
def solver_decreases(m, iters, tag, direction="gradient") -> bool:
    s = solver.GradientSolver(m)
    s.direction = direction
    s.max_iter = iters
    s.verbosity = 0
    s.line_search = "armijo"
    res = s.solve()
    if len(res.hist.J) < 2:
        return False
    J0, Jf = res.hist.J[0], res.hist.J[-1]
    print(f"   [{tag}] {direction}: J0={J0:.4e} -> Jf={Jf:.4e} (iter {res.iterations})")
    return bool(np.isfinite(Jf) and Jf < J0)
```

- **检查整体优化效果**：最终成本必须小于初始成本。
- `len(res.hist.J) < 2` —— 如果只跑了不到 2 轮就没法比较，判失败。
- `verbosity = 0` —— 静音求解器，避免自检输出被淹没。
- `tag` 参数（`"qubit"` / `"example"`）让输出能区分是哪个问题。

```python
def homotopy_runs() -> bool:
    m = ocp.QubitReset(tau=0.15, N=40, homotopy_name="kappa")
    path = np.linspace(0.2, 1.0, 4)
    c = continuation.HomotopyContinuation(m, path)
    c.solver.max_iter = 25
    c.solver.verbosity = 0
    c.verbose = False
    r = c.run()
    print(f"   [homotopy] final J={r.J:.4e} over {path.size} steps")
    return bool(np.isfinite(r.J))
```

- 用很小的规模（`N=40`、4 步、25 次迭代）—— **自检要快**，
  目的是"验证机制能工作"，不是"求最优解"。
- `c.verbose = False` —— 关掉延拓自己的逐步打印。

## 5.3 自检与 MATLAB 版数值的对照

本机实测的两边输出：

```
=== gradient OCP self check ===            ← MATLAB README 记录
[1] 梯度是下降方向      : qubit=PASS example=PASS
[2] 求解器成本下降       : qubit 0.316→0.175(60步)  example 4.554→4.494
[3] Adam 方向优化        : qubit 0.316→0.053
[4] 同伦延拓运行         : kappa 4 步 J=0.052
```

```
=== gradient OCP self check (Python) ===   ← 本次重写实测

[2] solver decreases cost      : qubit=PASS example=PASS
   [qubit] gradient: J0=3.1568e-01 -> Jf=1.7508e-01 (iter 60)
   [example] gradient: J0=4.5539e+00 -> Jf=4.4937e+00 (iter 9)
   [qubit] adam: J0=3.1568e-01 -> Jf=5.2739e-02 (iter 60)
```

**逐项对应：**

**这就是"重写正确"的证据链** —— 不是"我觉得对"，而是

# 六、复盘：框架层值得记住的设计模式

| 模式 | 在哪 | 好处 |
|---|---|---|
| **抽象基类** | `AbstractOCP` | 问题可替换，错误在实例化时暴露 |
| **策略模式** | `project()` 的多态 | 同一个求解器支持有/无约束问题 |
| **观察者模式** | `solver.observer` | 求解器不含任何绘图逻辑，回调可插拔 |
| **模板方法** | `HomotopyContinuation.run()` | 外壳固定流程，具体问题由 `set_homotopy` 决定 |
| **数据类** | `History` / `SolveResult` | 替代 struct，字段名与 MATLAB 保持一致 |
| **延迟导入** | `solve_reference()` / `show_live` 分支 | 解决循环依赖 + 避免不必要的外部依赖 |
| **退出码** | `validate_suite.py` | 自检可被 CI 直接使用 |
| **环境变量配置** | `demo_prolong.py` | 同一份代码支持"快跑"和"完整复现"两种模式 |
