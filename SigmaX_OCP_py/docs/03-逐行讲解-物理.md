# 一、先建立物理直觉（10 分钟版）

## 1.1 问题是什么

一个量子比特（qubit）放在有耗散的**浴**里，状态用密度矩阵的布居数表示：

$$
p(t) = \begin{bmatrix} p_e \\ p_r \\ p_i \end{bmatrix}
\quad\text{（激发态 / 弛豫态 / 相干项）}
$$

目标是：**用外加驱动把 p 拉到零**（"重置"），而且要**尽量快**。

可用的手是两路驱动幅度：

$$
u(t) = \begin{bmatrix} \lambda_x(t) \\ \lambda_z(t) \end{bmatrix}
$$

物理限制是幅度有上限：$0 \le \lambda_x \le \lambda_x^{\max}$，
$0 \le \lambda_z \le \lambda_z^{\max}$ ——
**这就是那个"盒约束"，也是为什么求解器要做投影。**

## 1.2 动力学与成本

演化方程是 **Lindblad 主方程**，在这个问题里被整理成线性形式：

$$
\frac{dp}{dt} = P(\theta, \Lambda)\, p + p_0(\theta, \Lambda)
$$

其中 $P$ 是一个 $3\times3$ 矩阵，$p_0$ 是一个 3 维向量，
两者都是控制变换 $(\theta, \Lambda)$ 的函数（**不是** $\lambda_x, \lambda_z$ 的函数）。
$\theta$ 和 $\Lambda$ 就是控制量的极坐标（见 1.3）。

> **关键设计**：物理方程里出现的是 $(\theta, \Lambda)$，
> 而我们要优化的是 $(\lambda_x, \lambda_z)$。
> 所以梯度必须**经链式法则穿过这个坐标变换**。
> 这就是 `control_transform` 和 `transform_jacobian` 存在的理由。

成本是**终端成本**（Mayer 型）：

$$
J = |p(\tau)|
$$

即"终点时刻状态向量的长度"。$J = 0$ 就是完美重置。

## 1.3 控制变换：直角坐标 → 极坐标

$$
\theta = \operatorname{atan2}(\lambda_x, \lambda_z), \qquad
\Lambda = \sqrt{\lambda_x^2 + \lambda_z^2}
$$

**注意 `atan2` 的参数顺序是"先 x 后 z"** —— 也就是从 **z 轴**量起的角度。
这和常见数学约定（从 x 轴量起）不同，看代码时要留意。

这套变换的好处：物理方程在极坐标下形式更简洁。
代价：$\Lambda = 0$ 处极坐标是**奇异的**（角度没定义），
所以代码里专门做了保护（见 4.2）。

## 1.4 梯度从哪来：庞特里亚金极值原理

"直接法"的普遍做法是**有限差分**：给每个控制采样点加个小扰动，
看成本变化多少。但那样要算 $2N$ 次（$N$ 是时间点数），太慢。

**庞特里亚金极值原理**（PMP）给出**解析梯度**，代价是两次积分：

1. **前向积分**状态方程 → 得到 $p(t)$ 整条轨迹
2. **后向积分协态方程** → 得到 $\mu(t)$ 整条轨迹
   （$\mu$ 是"影子价格"，衡量"终点状态对中间每个时刻的敏感度"）
3. 用 $\mu$ 和控制变换的雅可比**组装**出 $\nabla_u J$

总代价只有 2 次积分，与 $N$ 无关（线性复杂度）。

```
        U (2×N)
         │
         │ ① 极坐标变换
         ▼
   (theta, Lambda)
         │
         ├──② 前向 RK4 ────────► X = p(t)   (3×N)
         │                              │
         │                              ▼
         │                      J = |p(τ)|
         │                              │
         │                     ③ 末端协态 μ(τ) = -κ·p(τ)/|p(τ)|
         │                              │
         ├──④ 后向 RK4 ────────► Mu = μ(t)  (3×N)
         │                              │
         ▼                              │
   P, p0 及其对 (θ,Λ) 的偏导  ◄─────────┘
         │
         │ ⑤ 组装 + 链式法则穿过雅可比
         ▼
      G = ∂J/∂U  (2×N)
```

# 三、A 部分：模块级常量

```python
def _matlab_round(x: float) -> int:
    """MATLAB 的 ``round``：四舍五入，遇 .5 向远离 0 的方向进位。

    Python 内置 ``round`` 是"银行家舍入"（round(2.5) == 2），与原代码不一致，
    会改变 ``initial_control`` 里抛物线/常数段的拼接位置，所以必须显式模拟。
    """
    return int(np.floor(x + 0.5)) if x >= 0 else -int(np.floor(-x + 0.5))
```

**为什么需要这个函数**（这是个真实的坑）：

| 输入 | MATLAB `round` | Python `round` |
|---|---|---|
| 2.5 | 3 | **2**（银行家舍入：取最近的偶数） |
| 3.5 | 4 | **4** |
| 4.5 | 5 | **4** |

Python 的 `round` 用的是 **IEEE 754 默认的"就近取偶"**，
而 MATLAB 是"四舍五入、遇半进位"。

**影响在哪**：`initial_control` 里用 `round(n/2)` 决定"抛物段"和"常数段"的
拼接位置。如果 `N` 是奇数（比如 `N=5`），MATLAB 得 `round(2.5)=3`，
Python 得 `round(2.5)=2` —— **初始控制会不一样，后面整个优化轨迹就分岔了。**

**实现细节：**

- `np.floor(x + 0.5)` —— 对正数，这就是"四舍五入"。
- 负数要特殊处理：`int(np.floor(-x + 0.5))` 再取负。
  （实际上 `initial_control` 里 `n/2` 永远是正的，但写成通用函数更稳妥。）
- `int(...)` 把 `np.float64` 转成 Python 原生 `int`，用作切片索引更安全
  （numpy 整数也能当索引，但原生 int 更清晰）。

# 四、B 部分：契约实现（**必须读懂**）

## 4.1 类声明与默认值

```python
class QubitReset(AbstractOCP):
    n_state = 3
    n_control = 2
    name = "time-optimal qubit reset (sigma_x)"

    def __init__(self, **kwargs) -> None:
        super().__init__()
        self.omega_c: float = 1.0
        self.gamma: float = 10.0
        self.lambda_max = np.array([3.0, 2.0])
        self.p_initial = np.array([0.5, 0.0, 0.0])
        self.tau: float = 0.15
        self.N: int = 100
        self.homotopy_name: str = "kappa"
        self.homotopy_value: float = 1.0
        self.set(**kwargs)
```

**逐行：**

- `class QubitReset(AbstractOCP)` —— 继承抽象基类，从此**必须实现那 6 个方法**，
  否则 `QubitReset()` 会直接报错。这是继承 `ABC` 的最大好处。

- `n_state = 3` / `n_control = 2` —— **类属性**，覆盖基类的默认值 0。
  状态是 `[p_e, p_r, p_i]` 三维，控制是 `[λx, λz]` 二维。

- `super().__init__()` —— 调用父类的构造函数。
  **这一步不能省**！父类 `__init__` 负责设置 `tau`、`homotopy_value`、
  `homotopy_name`，不调用的话这些属性不存在。

  **MATLAB 对照**：MATLAB 里父类属性默认值会自动生效，不需要显式调用。
  Python 必须手动 `super().__init__()` —— **这是继承上的一个关键差异**。

- `self.gamma = 10.0` —— 退相干速率。**MATLAB 对照**：`obj.gamma = 10;`

- `self.lambda_max = np.array([3.0, 2.0])` ——
  控制上界。**MATLAB 是 `[3; 2]` 的 `(2,1)` 列向量，Python 用 `(2,)` 一维数组**。

  > **为什么改成 1 维？** Python/numpy 里一维数组更自然，
   > 需要广播时用 `[:, None]` 临时升维（项目里多处这么做）。
  > 代价是**每次广播都要记得加 `[:, None]`**，忘了就会悄悄算错。

- `self.p_initial = np.array([0.5, 0.0, 0.0])` —— 初始布居。

- `self.homotopy_name = "kappa"` —— 默认延拓族是 `kappa`（成本权重），
  另一个可选值是 `"tau"`（时间长度）。

- `self.set(**kwargs)` —— 应用用户传的参数，例如
  `QubitReset(tau=0.15, N=100, gamma=10, lambda_max=[3, 2])`。

## 4.2 `set()`：带类型转换的属性设置

```python
    def set(self, **kwargs) -> "QubitReset":
        for key, value in kwargs.items():
            if not hasattr(self, key):
                raise AttributeError(
                    f"{type(self).__name__} 没有属性 '{key}'；"
                    f"可用属性: {sorted(k for k in vars(self) if not k.startswith('_'))}"
                )
            if key in ("lambda_max", "p_initial"):
                value = np.asarray(value, dtype=float)
            setattr(self, key, value)
        return self
```

**和基类 `set` 的区别**：多了**自动类型转换**。

**为什么需要**？因为用户会自然地写成 `QubitReset(lambda_max=[3, 2])`
（传 Python 列表）。如果不转换，`self.lambda_max` 就是个 list，
后面 `self.lambda_max[:, None]` 会直接报 `TypeError: list indices must be integers`。
自动转成 numpy 数组，用户体验更好。

- `np.asarray(value, dtype=float)` ——
  如果 `value` 已经是 ndarray 就**不复制**（`asarray` 的特点），
  是 list 就转换。同时强制 `float` 类型，避免整数数组做除法时出意外。

- `sorted(k for k in vars(self) if not k.startswith('_'))` ——
  `vars(self)` 返回实例的 `__dict__`（属性字典），过滤掉下划线开头的私有属性，
  排序后放进错误信息里，**用户拼错参数名时能立刻看到正确名字**。

  > `type(self).__name__` 而不是写死 `"QubitReset"`：
  > 这样如果有人继承 `QubitReset`，报错信息里显示的是子类名。

## 4.3 `time_grid` / `initial_state` / `control_bounds` / `project`

```python
    def time_grid(self, N=None) -> np.ndarray:
        if N is None:
            N = self.N
        return np.linspace(0.0, self.tau, int(N))
```

- **MATLAB 对照**：`tg = linspace(0, obj.tau, N);` —— 完全一样。
- 注意用的是 `self.tau` 而不是硬编码 —— 这样**延拓改 `tau` 时，
  时间格点会自动跟着变**。这是延拓机制能工作的前提。

```python
    def initial_state(self) -> np.ndarray:
        return np.array([0.5, 0.0, 0.0])
```

⚠️ **这里有个值得注意的地方**：方法**硬编码**返回 `[0.5, 0, 0]`，
而**没有**用 `self.p_initial`。

这是**忠实保留 MATLAB 版行为**（MATLAB 版 `initialState(~)` 也是硬编码）。
后果是：如果你改了 `p_initial`，`cost_gradient` 里的前向积分会用新值，
但 `initial_state()` 仍然返回 `[0.5,0,0]` —— 两者不一致。

**兼容性考虑**：为了数值能和 MATLAB 逐项对齐，本项目保持原样。
**如果你要改初态**，应该把这里改成 `return self.p_initial.copy()`。
（`.copy()` 很重要，否则调用方改了返回值会污染模型。）

```python
    def control_bounds(self):
        return np.zeros(2), self.lambda_max.copy()
```

- 下界是全 0（驱动幅度不能为负），上界是 `lambda_max`。
- `.copy()` —— 返回副本，防止调用方修改返回值时意外改到模型的 `lambda_max`。

```python
    def project(self, U):
        lo, hi = self.control_bounds()
        return np.clip(U, lo[:, None], hi[:, None])
```

- **`np.clip(数组, 下界, 上界)`** 一步完成"先 max 再 min"的裁剪。
  **MATLAB 对照**：`max(lo, min(hi, U))`。
- `lo[:, None]` / `hi[:, None]` ——
  **把 `(2,)` 变成 `(2,1)`，才能和 `U` 的 `(2,N)` 广播**。
  没有这个，`np.clip(U, lo, hi)` 会按最后一维（时间维）去对，**算出的结果是错的**。

  > 这是 numpy 广播最阴险的地方：**形状不对往往不报错，只是默默地按错误的
  > 维度对齐**。所以本项目里凡是 `(n_control,)` 要和 `(n_control, N)` 运算，
  > 一律加 `[:, None]`。你自己写时也要养成这个习惯。

## 4.4 `cost_gradient()` —— **整个项目的心脏**

```python
    def cost_gradient(self, tg, U):
        theta, Lam = self._control_transform(U)
        kappa = self.homotopy_value

        X = self._forward_integrate(tg, theta, Lam, self.p_initial)

        pT = X[:, -1]
        nrm = float(np.sqrt(np.sum(pT**2)))
        if nrm < 1e-14:
            nrm = 1e-14
        J_ter = nrm
        mu0 = -kappa * pT / nrm
        Mu = self._backward_integrate(tg, theta, Lam, mu0)

        G = -self._gradient_at(X, Mu, theta, Lam)

        if kappa < 1.0:
            lm = self.lambda_max[:, None]
            Lr = (1.0 - kappa) / self.tau * np.sum(U / lm, axis=0)
            J = kappa * J_ter + AbstractOCP.trapezoid(tg, Lr)
            dLr = ((1.0 - kappa) / self.tau / self.lambda_max)[:, None]
            G = G + dLr
        else:
            J = J_ter

        return float(J), X, Mu, G
```

**这段是全文件最重要的 20 行**，逐步拆：

### ① 控制 → 极坐标

```python
theta, Lam = self._control_transform(U)
```
把 `(2, N)` 的驱动幅度转成 `(N,)` 的角度和 `(N,)` 的模长。

### ② 前向积分状态

```python
X = self._forward_integrate(tg, theta, Lam, self.p_initial)
```
从初态 $p(0)$ 出发，用 RK4 沿时间积分 $\dot p = Pp + p_0$，
得到整条轨迹 `X`，形状 `(3, N)`。

### ③ 终端成本与启动协态

```python
pT = X[:, -1]                                # 终点状态 (3,)
nrm = float(np.sqrt(np.sum(pT**2)))          # |p(τ)|  ← 这就是成本
if nrm < 1e-14:
    nrm = 1e-14                              # 防止下一步除以 0
J_ter = nrm
mu0 = -kappa * pT / nrm                      # 末端协态
```

- `X[:, -1]` —— 最后一列，即终点状态。
  **MATLAB 对照**：`X(:, end)`，`end` 对应 Python 的 `-1`。
- `np.sum(pT**2)` —— 向量各分量平方和（**MATLAB 对照**：`sum(pT.^2)`）。
  注意这里**没写 `axis`**，因为 `pT` 是一维的，`sum` 默认对所有元素求和 = 标量。
- `nrm < 1e-14` 的保护：如果状态已经完美归零，后面 `pT / nrm` 会除零。
  **MATLAB 对照**：`if nrm < 1e-14, nrm = 1e-14; end`。

- **`mu0 = -kappa * pT / nrm` 是怎么来的？**
  这是 PMP 的**自然边界条件**（横截条件）。
  因为终端成本是 $J = |p(\tau)|$，对 $p(\tau)$ 求导得
  $\nabla_{p(\tau)} J = p(\tau)/|p(\tau)|$，
  而协态的终端条件按惯例带个负号：
  $\mu(\tau) = -\kappa \cdot p(\tau)/|p(\tau)|$。

  **这里出现的 $\kappa$ 就是延拓参数** —— 它同时缩放终端成本权重
  和协态的终端条件，保证梯度的一致性。

### ④ 后向积分协态

```python
Mu = self._backward_integrate(tg, theta, Lam, mu0)
```
从 $\mu(\tau) = \mu_0$ 出发，**逆着时间**积分协态方程
$\dot\mu = -A^\top \mu$，得到整条协态轨迹 `(3, N)`。

### ⑤ 组装梯度（注意负号）

```python
G = -self._gradient_at(X, Mu, theta, Lam)
```

- `_gradient_at` 返回的是"沿极坐标方向的敏感度"，
  经雅可比链式法则映射回 $(\lambda_x, \lambda_z)$ 空间。
- **那个负号是关键的**：PMP 里 Hamilton 函数定义为
  $H = \mu^\top(Pp + p_0)$，而 $\nabla_u J = -\partial H/\partial u$。
  负号就来自这里。**如果漏了这个负号，梯度方向会完全反掉，
  优化会发散或用"最陡上升"去爬山。**

  > 这种符号错误是最难查的 bug 之一 —— 代码能跑、不报错，
  > 但结果完全错。**验证手段就是"下降方向检验"**：
  > 沿 `-G` 走一小步，成本必须下降。走反了立刻就能发现。

### ⑥ 可选的运行成本（延拓用）

```python
if kappa < 1.0:
    lm = self.lambda_max[:, None]
    Lr = (1.0 - kappa) / self.tau * np.sum(U / lm, axis=0)
    J = kappa * J_ter + AbstractOCP.trapezoid(tg, Lr)
    dLr = ((1.0 - kappa) / self.tau / self.lambda_max)[:, None]
    G = G + dLr
else:
    J = J_ter
```

- 当 `kappa < 1` 时，成本变成

  $$
  J = \kappa |p(\tau)| + \frac{1-\kappa}{\tau}\int_0^\tau \sum_i \frac{u_i}{u_i^{\max}}\,dt
  $$

  加的第二项是**正则化运行成本**：惩罚控制幅度，让问题更容易求解。

- `U / lm` —— 逐元素除以 `lambda_max`（每路驱动除以各自的上限），
  得到"归一化幅度"。
  `np.sum(..., axis=0)` 沿控制维求和 → `(N,)`。
  **MATLAB 对照**：`sum(U ./ obj.lambdaMax, 1)`。

- `dLr` 是运行成本对 $u$ 的梯度（$\partial L_r/\partial u_i = (1-\kappa)/(\tau u_i^{\max})$），
  加在 `G` 上。`lm` 用 `[:, None]` 升维成 `(2,1)` 才能和 `(2,N)` 相加。

- **`kappa = 1` 时就是原问题**（纯终端成本），这也是 `homotopy_value` 默认值的含义。

## 4.5 `set_homotopy()` —— 延拓的分派点

```python
    def set_homotopy(self, v: float) -> None:

            self.tau = v
        self.homotopy_value = v
```

- **MATLAB 对照**：

  ```matlab
  if strcmpi(obj.homotopyName, 'tau')
      obj.tau = v;

  obj.homotopyValue = v;
  ```

- 这是**重写**（override）基类的 `set_homotopy`。
  基类版本只存值；这个版本在 `homotopy_name == 'tau'` 时**额外修改 `tau`**。

- 于是调用 `c.run()` 时，`HomotopyContinuation` 每步调用 `set_homotopy(tau_i)`，
  都会：①改 `self.tau` → ②让下一次 `time_grid()` 返回新的时间范围。
  **这就是"时域延拓"能工作的完整机制。**

- `kappa` 族不需要改别的，所以只走 `homotopy_value = v` 那一行。

## 4.6 `solve_reference()`

```python
    def solve_reference(self):
        from ..solver.gradient_solver import GradientSolver   # 延迟导入，避免循环
        s = GradientSolver(self)
        s.direction = "gradient"
        s.line_search = "armijo"
```

  > 这是 Python 项目里处理循环依赖的标准手法。你也可以用
  > `import ... # noqa: F401` 之类的技巧，但"函数内延迟导入"最清晰。

- `s.solve(U0)` —— 只传 `U0` 不传 `tg`，所以内部会用 `solver.N`（默认 100）。

# 五、C 部分：控制变换与雅可比（**必须读懂**）

## 5.1 变换本身

```python
    @staticmethod
    def _control_transform(U):
        ux = U[0, :]
        uz = U[1, :]
        theta = np.arctan2(ux, uz)
        Lam = np.sqrt(ux**2 + uz**2)
        return theta, Lam
```

- `U[0, :]` —— 第 0 行（$\lambda_x$ 那一路），`U[1, :]` 是 $\lambda_z$。
  **MATLAB 对照**：`U(1,:)` / `U(2,:)` —— 注意 **1→0**。
- `np.arctan2(ux, uz)` —— **参数顺序：先 $\lambda_x$，后 $\lambda_z$**，
  即从 **z 轴**量起的角度。**MATLAB 对照**：`atan2(ux, uz)`。
- 变量名用 `Lam` 而不是 `Lambda`：`lambda` 是 Python 关键字，`Lambda` 容易看混，
  所以简写成 `Lam`（MATLAB 里叫 `Lambda`）。

## 5.2 雅可比（链式法则的关键）

```python
    @staticmethod
    def _transform_jacobian(theta, Lam):
        invL = 1.0 / np.maximum(Lam, 1e-12)
        tx = np.cos(theta) * invL      # d theta  / d lambda_x
        tz = -np.sin(theta) * invL     # d theta  / d lambda_z
        lx = np.sin(theta)             # d Lambda / d lambda_x
        lz = np.cos(theta)             # d Lambda / d lambda_z
        small = Lam < 1e-9
        tx[small] = 0.0
        tz[small] = 0.0
        return tx, tz, lx, lz
```

**这 4 个量就是链式法则需要的偏导数。** 从
$\lambda_x = \Lambda\sin\theta$、$\lambda_z = \Lambda\cos\theta$ 反解可得：

$$
\frac{\partial\theta}{\partial\lambda_x} = \frac{\cos\theta}{\Lambda},\quad
\frac{\partial\theta}{\partial\lambda_z} = -\frac{\sin\theta}{\Lambda},\quad
\frac{\partial\Lambda}{\partial\lambda_x} = \sin\theta,\quad
\frac{\partial\Lambda}{\partial\lambda_z} = \cos\theta
$$

**逐行：**

- `invL = 1.0 / np.maximum(Lam, 1e-12)` —— $1/\Lambda$。
  用 `np.maximum(Lam, 1e-12)` **把分母托住**，避免 $\Lambda=0$ 时除零得到 `inf`。
  **MATLAB 对照**：`invL = 1./max(Lambda, 1e-12);`

- `tx = cos(theta) * invL` —— 即 $\partial\theta/\partial\lambda_x$。
- `tz = -sin(theta) * invL` —— 即 $\partial\theta/\partial\lambda_z$。
- `lx = sin(theta)` / `lz = cos(theta)` —— $\partial\Lambda/\partial\lambda_{x,z}$。

- **奇异点处理**：

  ```python
  small = Lam < 1e-9
  tx[small] = 0.0
  tz[small] = 0.0
  ```

  极坐标在 $\Lambda = 0$ 处**角度没有定义**（原点处所有角度都对）。
  原始推导的做法是**把角度的偏导直接置零**，避免 $0/0$。
  注意只处理了 `tx`/`tz`（角度相关），`lx`/`lz` 是 $\sin/\cos$，在原点也有定义，不用管。

  > **这是"物理/数学上的权宜处理"**，不是笔误。这类处理在数值优化里很常见，
  > 关键是**要清楚它会影响什么**：在 $\Lambda\to0$ 附近梯度的角度分量被抹掉了。
  > 好在控制有下界 0，且实际最优解通常不会停在原点。

- `tx[small] = 0.0` —— 布尔数组索引赋值（**boolean mask indexing**）。
  `small` 是布尔数组，`tx[small] = 0` 表示"把所有 `small` 为 True 的位置赋 0"。
  **MATLAB 对照**：`tx(small) = 0;` —— 语法几乎一样。

  > `tx = cos(theta) * invL` 产生的是**新数组**，所以原地改它是安全的，
  > 不影响 `theta` 或 `Lam`。这点和 `np.clip` 之类返回新数组一样。

# 六、D 部分：RK4 积分器（**必须读懂**）

## 6.1 为什么用 RK4

方程 $\dot p = Pp + p_0$ 是**线性时变**的，控制在每个采样点内视为常数。
RK4（四阶 Runge-Kutta）是标准的高精度单步法：每步算 4 次斜率再加权平均，
局部误差 $O(h^5)$、全局误差 $O(h^4)$。

对于这个精度要求（要算到 1e-5 级别的梯度），RK4 是合适的默认选择。

## 6.2 通用 RK4 单步

```python
    @staticmethod
    def _rk4(f, x, dt):
        """经典四阶 Runge-Kutta 单步（向量版）。"""
        k1 = f(x)
        k2 = f(x + 0.5 * dt * k1)
        k3 = f(x + 0.5 * dt * k2)
        k4 = f(x + dt * k3)
        return x + (dt / 6.0) * (k1 + 2.0 * k2 + 2.0 * k3 + k4)
```

**逐行（这就是教科书公式）：**

- `k1 = f(x)` —— 起点斜率。
- `k2 = f(x + 0.5*dt*k1)` —— 用 $k_1$ 走半步得到的斜率。
- `k3 = f(x + 0.5*dt*k2)` —— 用 $k_2$ 走半步得到的斜率。
- `k4 = f(x + dt*k3)` —— 用 $k_3$ 走一整步得到的斜率。
- 加权平均：$\frac{1}{6}(k_1 + 2k_2 + 2k_3 + k_4)$ ——
  中间两个斜率权重是两端的两倍（Simpson 法则的思想）。

**`f` 是一个函数**（Python 里函数是一等公民，可以当参数传）。
调用方用 `lambda` 传入具体的右端项。

**MATLAB 对照**：`rk4(~, f, x, dt)`，其中 `~` 表示 `obj` 参数不用 ——
Python 用 `@staticmethod` 表达同样的意思。

## 6.3 前向积分

```python
    def _forward_integrate(self, tg, theta, Lam, X0):
        N = tg.size
        X = np.zeros((self.n_state, N))
        X[:, 0] = X0
        for k in range(N - 1):
            dt = tg[k + 1] - tg[k]
            A, b = self._mat_vec(theta[k], Lam[k])
            X[:, k + 1] = self._rk4(lambda x, A=A, b=b: A @ x + b, X[:, k], dt)
        return X
```

**逐行（注意下标平移）：**

- `N = tg.size` —— 时间点数。**MATLAB 对照**：`numel(tg)`。
- `X = np.zeros((self.n_state, N))` —— 预分配 `(3, N)`。
  **MATLAB 对照**：`zeros(obj.nState, N)`。
- `X[:, 0] = X0` —— 第 0 列放初态。
  **MATLAB 对照**：`X(:, 1) = X0;` —— **1 → 0**。

- `for k in range(N - 1):` ——
  **MATLAB 对照**：`for k = 1:N-1`。
  Python 的 `range(N-1)` 给出 `0, 1, ..., N-2`，正好对应 MATLAB 的 `1, ..., N-1`。

- `dt = tg[k + 1] - tg[k]` —— 步长。这个下标在两个语言里**写法相同**
  （因为同样是"当前点和下一点"），**但数值不同**：MATLAB 的 `k=1` 对应 Python 的 `k=0`。

- `A, b = self._mat_vec(theta[k], Lam[k])` ——
  取**第 k 个采样点**的矩阵和向量（分段常数控制）。
  **MATLAB 对照**：`obj.matVec(theta(k), Lambda(k))`。

- `lambda x, A=A, b=b: A @ x + b` —— **两个要点**：
  1. `A @ x + b` 就是 $\dot p = Ap + b$ 的右端。
     **`@` 是矩阵乘法**（**MATLAB 对照**：`A*x`）。
  2. **`A=A, b=b` 这种写法叫"默认参数绑定"** ——
     它把当前循环变量 `A`、`b` 的值**立刻固化进 lambda**。
     如果写成 `lambda x: A @ x + b`，lambda 里引用的是**变量名** `A`，
     到真正调用时会取"那一刻"的值 —— 虽然在本例里因为立即调用所以没问题，
     但**在延迟调用的场景下会导致所有 lambda 都用最后一个 A**，
     这是 Python 闭包最经典的陷阱。显式绑定是防御性写法。

- `X[:, k + 1] = self._rk4(...)` —— 结果写回下一列。
  **实际执行顺序**：`k=0` 时算 `X[:,1]`（用 `X[:,0]`），
  `k=1` 时算 `X[:,2]`（用 `X[:,1]`）…… 逐点推进。

## 6.4 后向积分（**最容易写错的地方**）

```python
    def _backward_integrate(self, tg, theta, Lam, Mu0):
        N = tg.size
        Mu = np.zeros((self.n_state, N))
        Mu[:, N - 1] = Mu0
        for k in range(N - 1, 0, -1):
            dt = tg[k] - tg[k - 1]
            A, _ = self._mat_vec(theta[k - 1], Lam[k - 1])
            Mu[:, k - 1] = self._rk4(lambda mu, A=A: A.T @ mu, Mu[:, k], dt)
        return Mu
```

**对照 MATLAB：**

```matlab
Mu = zeros(obj.nState, N);
Mu(:, N) = Mu0;                        % ← 终点在最后一列
for k = N:-1:2                         % ← 从 N 倒数到 2
    dt = tg(k) - tg(k-1);
    [A, ~] = obj.matVec(theta(k-1), Lambda(k-1));
    Mu(:, k-1) = obj.rk4(@(mu) A'*mu, Mu(:, k), dt);
end
```

**逐行拆解：**

- `Mu[:, N - 1] = Mu0` —— 终点条件放在**最后一列**。
  **MATLAB 对照**：`Mu(:, N) = Mu0` —— MATLAB 的 `N` ↔ Python 的 `N-1`。

- `for k in range(N - 1, 0, -1):` —— ⚠️ **重点**。
  Python 的 `range(start, stop, step)` **右端不含**。
  - `range(N-1, 0, -1)` 生成 `N-1, N-2, ..., 1`。
  - MATLAB 的 `N:-1:2` 生成 `N, N-1, ..., 2`。
  - **两者正好差 1** —— 因为 Python 的 `k` 就是 MATLAB 的 `k-1`。

  **记忆法**：把 MATLAB 的下标整体减 1，
  `for k = N:-1:2` → `for k in range(N-1, 1-1, -1)` = `range(N-1, 0, -1)`。

- `A, _ = self._mat_vec(...)` ——
  **`_` 表示"第二个返回值我不需要"**。
  `_mat_vec` 返回 `(A, b)`，后向积分只需要 `A`（因为协态方程没有 $b$ 项）。
  **MATLAB 对照**：`[A, ~] = obj.matVec(...)`。

- `theta[k - 1], Lam[k - 1]` —— 用**前一个**采样点的参数，因为向后走一步是从
  第 `k` 点到第 `k-1` 点，控制取这一段（分段常数）。

- `A.T @ mu` —— 协态方程 $\dot\mu = -A^\top\mu$ 的右端。
  **`A.T` 是转置**（**MATLAB 对照**：`A'`）。
  > 注意：MATLAB 的 `'` 是**共轭转置**，Python 的 `.T` 是**纯转置**。
  > 对实数矩阵两者相同。本项目 $A$ 是实矩阵，所以没差别，
  > 但如果以后处理复数量子力学（密度矩阵用复数），**必须用 `.conj().T`**。

- **为什么是 $-A^\top$ 而不是 $A^\top$？**
  因为协态方程是从"反向时间"推出来的。代码里用了一个等价技巧：
  **不真的倒着积分，而是把 $s=-t$ 当新时间轴，正向积分 $A^\top\mu$**，
  这样可以直接复用同一个 `_rk4`。

  > 代码注释里写的 `f = @(mu) A'*mu; d mu / d s with s = -t`
  > 就是这个意思。**变量名 `k` 从大到小、但每一步都在"向前"积分 $\mu$**，
  > 这个反直觉之处是后向积分最容易看晕的地方。

# 七、E 部分：梯度组装（**必须读懂**）

## 7.1 MATLAB 版长什么样

```matlab
function G = gradientAt(obj, X, Mu, theta, Lambda)
    N = numel(theta);
    [Pth, p0th] = obj.matVecTheta(theta, Lambda);   % 3x3xN, 3xN
    [Pla, p0la] = obj.matVecLambda(theta, Lambda);
    Hth = zeros(1, N); Hla = zeros(1, N);
    for k = 1:N
        Hth(k) = Mu(:, k)' * (Pth(:,:,k)*X(:, k) + p0th(:, k));
        Hla(k) = Mu(:, k)' * (Pla(:,:,k)*X(:, k) + p0la(:, k));
    end
    [tx, tz, lx, lz] = obj.transformJacobian(theta, Lambda);
    G = [ tx .* Hth + lx .* Hla ;
          tz .* Hth + lz .* Hla ];
end
```

**先理解 `Hth` / `Hla` 是什么：**

- `Pth(:,:,k)` 是 $\partial P/\partial\theta$ 在第 $k$ 个采样点的值（$3\times3$）。
- `Pth(:,:,k)*X(:,k)` 是 $\frac{\partial}{\partial\theta}(Px)$ —— 矩阵对参数求导。
- 加上 `p0th(:,k)`（$\partial p_0/\partial\theta$）就是
  $\frac{\partial}{\partial\theta}(Px + p_0)$，也就是**动力学右端对 $\theta$ 的偏导**。
- 再左乘 `Mu(:,k)'`（协态转置）—— 这一步就是**把协态当作权重**，
  衡量"这一时刻动力学变化对总成本的贡献"。

所以 `Hth(k)` 就是 $\mu^\top \frac{\partial}{\partial\theta}(Pp+p_0)$
在第 $k$ 点的值 —— 通俗说：**"$\theta$ 在该点变化一点，成本会变多少"**。

`Hla(k)` 同理，只是对 $\Lambda$ 求导。

**最后两行是链式法则**：

$$
\frac{\partial J}{\partial\lambda_x} = \frac{\partial J}{\partial\theta}\cdot\frac{\partial\theta}{\partial\lambda_x}
+ \frac{\partial J}{\partial\Lambda}\cdot\frac{\partial\Lambda}{\partial\lambda_x}
= H_\theta \cdot t_x + H_\Lambda \cdot l_x
$$

（$\lambda_z$ 那一路同理。）这正好对应：

```matlab
G = [ tx .* Hth + lx .* Hla ;
      tz .* Hth + lz .* Hla ];
```

## 7.2 Python 版：用 einsum 替代循环

```python
    def _gradient_at(self, X, Mu, theta, Lam):
        Pth, p0th = self._mat_vec_theta(theta, Lam)      # (3,3,N), (3,N)
        Pla, p0la = self._mat_vec_lambda(theta, Lam)     # (3,3,N), (3,N)

        Hth = np.einsum("ik,ik->k", Mu, p0th) + np.einsum("ik,ijk,jk->k", Mu, Pth, X)
        Hla = np.einsum("ik,ik->k", Mu, p0la) + np.einsum("ik,ijk,jk->k", Mu, Pla, X)

        tx, tz, lx, lz = self._transform_jacobian(theta, Lam)
        return np.vstack([tx * Hth + lx * Hla, tz * Hth + lz * Hla])
```

### `np.einsum` 是什么

**`einsum` = Einstein summation（爱因斯坦求和约定）**：
用一串字母标签描述"哪些维度相乘、哪些维度求和"。

**读懂标签记法**：输入写 `"ik,ik->k"`，意思是
- `Mu` 的维度标签是 `i,k`
- `p0th` 的维度标签是 `i,k`
- 输出是 `k`
- 出现在输入但**没出现在输出**的标签（这里是 `i`）→ **要对该维度求和**

所以 `"ik,ik->k"` 就是：

```
结果[k] = Σ_i  Mu[i,k] * p0th[i,k]
```

**对应 MATLAB**：`sum(Mu(:,k) .* p0th(:,k))`，
即 `Mu(:,k)' * p0th(:,k)`（因为 $\mu^\top v = \sum_i \mu_i v_i$）。

第二个更复杂：`"ik,ijk,jk->k"`
- `Mu` 是 `i,k`
- `Pth` 是 `i,j,k`
- `X` 是 `j,k`
- 输出 `k`，所以 `i` 和 `j` **都要求和**

```
结果[k] = Σ_i Σ_j  Mu[i,k] * Pth[i,j,k] * X[j,k]
```

**逐步对应 MATLAB**：

| MATLAB | 含义 | einsum |
|---|---|---|
| `Pth(:,:,k) * X(:,k)` | $\sum_j P_{ij}X_j$（矩阵乘向量） | `i,j,k` 和 `j,k` 对 `j` 求和 → `i,k` |
| `Mu(:,k)' * (...)` | $\sum_i \mu_i(\cdot)_i$ | 再对 `i` 求和 → `k` |

所以两层 einsum 合起来**精确等价于**MATLAB 版那个 `for k = 1:N` 循环。

### 为什么改成 einsum

| | MATLAB 循环 | einsum |
|---|---|---|
| 写法 | 逐点循环 $N$ 次 | 一行 |
| 速度 | 每次迭代有解释器开销 | 底层 C 循环，快数倍 |
| 可读性 | 直观但要脑补下标 | 需要学会读标签 |

`einsum` 的**好处是"一次表达整个求和"**，numpy 会在 C 层完成，
在 `N=500`、上千次迭代的场景下差别明显。

> **性能实测结论（重要）**：本项目实测过把 RK4 内联（省掉每步创建 lambda），
> 只快了 **3%**；真正的瓶颈是 `_mat_vec` 里大量的**标量** numpy 运算。
> 想进一步提速，方向是**把 `_mat_vec` 向量化**（一次算所有采样点），
> 而不是抠 RK4 的函数调用。

### 最后两行

```python
return np.vstack([tx * Hth + lx * Hla, tz * Hth + lz * Hla])
```

- `tx * Hth + lx * Hla` —— 逐元素乘加，得到 `(N,)`，即 $\partial J/\partial\lambda_x$。
- `tz * Hth + lz * Hla` —— 同理，$\partial J/\partial\lambda_z$。
- `np.vstack([...])` —— **竖直堆叠**两个 `(N,)` 数组 → `(2, N)`。
  **MATLAB 对照**：`[ ... ; ... ]` 分号换行的矩阵拼接。

## 8.1 谱密度

```python
    def _spec(self, omega):
        """谱密度 J(omega)（洛伦兹型）。"""
        wc = self.omega_c
        return np.pi * omega * wc**2 / (omega**2 + wc**2)

    def _dspec(self, omega):
        """d J / d omega。"""
        wc = self.omega_c
        return np.pi * wc**2 * (wc**2 - omega**2) / (omega**2 + wc**2) ** 2
```

- `_spec` 是**洛伦兹谱密度**：描述"环境在不同频率上有多强的耦合"。
  `omega_c` 是截止频率。
- `_dspec` 是**它的导数**。**为什么需要导数**？
  因为 $\Gamma_\pm$ 依赖 $\textrm{spec}(2\Lambda)$，而 $\Lambda$ 是优化变量，
  所以链式法则要求 $\Gamma_\pm$ 对 $\Lambda$ 的偏导里必然出现 $\textrm{spec}'$。

**MATLAB 对照**：`spec(obj, omega)` / `dspec(obj, omega)` —— 完全一致。

## 8.2 $\Gamma_z$ 及其偏导

```python
    def _gz(self, th, la):
        return np.pi * np.sin(th) ** 2

    def _gz_th(self, th, la):
        return 2.0 * np.pi * np.sin(th) * np.cos(th)

    def _gz_la(self, th, la):
        # MATLAB: 0*th  —— 保留同样的写法，标量与数组都能正确广播
        return 0.0 * th
```

**命名规则（本节通用）**：

| 后缀 | 含义 |
|---|---|
| 无后缀 | 函数本身，如 `_gz` = $\Gamma_z$ |
| `_th` | 对 $\theta$ 的偏导，如 `_gz_th` = $\partial\Gamma_z/\partial\theta$ |
| `_la` | 对 $\Lambda$ 的偏导，如 `_gz_la` = $\partial\Gamma_z/\partial\Lambda$ |

**逐行：**

- $\Gamma_z = \pi\sin^2\theta$。
- 对 $\theta$ 求导：$\frac{d}{d\theta}\pi\sin^2\theta = 2\pi\sin\theta\cos\theta$ ✓
- **对 $\Lambda$ 求导是 0** —— 因为 $\Gamma_z$ 里根本没有 $\Lambda$。
  原代码写 `return 0*th`，这里保留同样写法。

  > **为什么要写成 `0.0 * th` 而不是直接 `return 0.0`？**
  > 因为 `th` 可能是标量（`_mat_vec` 单点调用），也可能是数组
  > （`_mat_vec_theta` 全采样点调用）。
  > `0.0 * th` 会自动**返回与 `th` 同形状**的结果，保证后续广播不出错。
  > 直接返回 `0.0` 标量虽然通常也能广播，但显式保持形状更安全、更省心。

## 8.3 $\Gamma_\pm$ 与那个**奇点处理**（重点看这个）

```python
    def _gp(self, th, la):
        with np.errstate(invalid="ignore", divide="ignore"):
            re = 0.5 * self._spec(2 * la) * (1.0 / np.tanh(la) + 1.0) * np.cos(th) ** 2
        re = np.where(np.isnan(re), 0.0, re)
        re = re + np.where(np.asarray(la) == 0, 1.0, 0.0) * (0.5 * np.pi * np.cos(th) ** 2)
        return re
```

**这段看起来很怪，但逻辑是自洽的。** 拆开讲：

### ① 数学上的奇点

公式里有 $1/\tanh\Lambda$。当 $\Lambda \to 0$ 时，$\tanh\Lambda \to 0$，
所以 $1/\tanh\Lambda \to \infty$ —— **在 $\Lambda=0$ 处发散**。

### ② 为什么"NaN 然后置零"能正确处理

关键在于 **$\textrm{spec}(0) = 0$**：

$$
\textrm{spec}(2\Lambda)\Big|_{\Lambda=0} = \frac{\pi\cdot 0 \cdot \omega_c^2}{0 + \omega_c^2} = 0
$$

所以整项是 **$0 \times \infty$**，而 IEEE 754 规定 $0\times\infty = \mathbf{NaN}$。

于是：
1. numpy 算出 `NaN`；
2. `np.isnan(re)` 找出来；
3. `np.where(..., 0.0, re)` 把它**置为 0**；
4. 再加上 $( \Lambda=0$ 时的解析极限项$)$ —— 也就是第二行那个
   `0.5*pi*cos(th)**2`。

**净效果**：在 $\Lambda=0$ 处直接用了解析极限值，绕开了数值奇点。

### ③ `np.errstate(...)` 是干什么的

numpy 默认对 `0/0`、`inf-inf` 这类操作**打印 RuntimeWarning**。
`with np.errstate(invalid="ignore", divide="ignore"):` 是一个
**上下文管理器**，只在这段代码内**抑制这些警告**。

**为什么要抑制**？因为我们**故意**制造 NaN 再处理它 —— 这是设计的一部分，
不是错误。不抑制的话，每次迭代都会刷一堆警告，淹没真正的错误信息。

> ⚠️ **重要**：`np.errstate` 只关闭**警告**，不改变计算结果，
> 也**不该用来掩盖真正的 bug**。这里之所以正当，是因为
> 下一行 `np.where(np.isnan(re), 0.0, re)` **显式地处理了** NaN。

### ④ `np.where(np.asarray(la) == 0, 1.0, 0.0)`

这是"**制作 0/1 掩码**"的写法：

- `np.asarray(la) == 0` —— 布尔数组（或标量布尔）。
- `np.where(条件, 1.0, 0.0)` —— 条件为真处取 1.0，否则取 0.0。
- **MATLAB 对照**：`(la == 0)` 直接当数值用（MATLAB 里 `true` 就是 1）。
  Python 里布尔参与乘法虽然也能算，但显式转成 0/1 更清晰、形状更可控。

所以整句是"**当 $\Lambda = 0$ 时，加上解析极限项**"。

### ⑤ `_gp_la` 里的情况更复杂一点

```python
    def _gp_la(self, th, la):
        with np.errstate(invalid="ignore", divide="ignore"):
            re = (
                self._dspec(2 * la) * (1.0 / np.tanh(la) + 1.0)
                - 0.5 * self._spec(2 * la) * (1.0 / np.sinh(la)) ** 2
            ) * np.cos(th) ** 2
        re = np.where(np.isnan(re), 0.0, re)
        re = re + np.where(np.asarray(la) == 0, 1.0, 0.0) * (self._dspec(0) * np.cos(th) ** 2)
        return re
```

- 这里还要处理 $1/\sinh\Lambda$（同样在 $\Lambda=0$ 发散）。
- 注意 $\textrm{dspec}(0) = \pi \ne 0$，所以第一项是 $\pi\times\infty = \infty$（不是 NaN），
  第二项是 $0\times\infty = \text{NaN}$，两者相减仍是 NaN → 被置零 → 再加解析项。
  **最终数学上是正确的**，只是路径绕。
- `_gm_la` 里最后加的解析项带**负号**（`-self._dspec(0) * ...`），
  因为 $\Gamma_-$ 的定义里是 $(1/\tanh - 1)$，符号不同。

> **这一节是你的主场**：这些公式是你自己推的，
> 所以面试时可以**完整展开讲** —— 从 Lindblad 方程出发、Hamilton 量怎么定义、
> 怎么得到 $\Gamma_\pm$、怎么用 PMP 得到协态方程、链式法则具体怎么走。
> `descriptor/main.tex` 里的这份推导，本身就是你最有说服力的作品集。
>
> 这里唯一的"技术难点"是重写层面：**$0\times\infty$ 必须靠 NaN 中转才能被识别**。
> 如果面试官追问实现细节，这一点很值得讲 —— 它说明你不只懂数学，
> 也懂浮点运算的边界行为。

## 8.4 矩阵 $P$ 与向量 $p_0$（单点版）

```python
    def _mat_vec(self, th, la):
        g = self.gamma
        Gz = self._gz(th, la)
        Gp = self._gp(th, la)
        Gm = self._gm(th, la)
        c = np.cos(th)
        s = np.sin(th)

        A = np.zeros((3, 3))
        A[0, 0] = -g * (4 * Gz * s**2 + (Gp + Gm) * (1 + c**2))
        A[0, 1] = g * (4 * Gz - Gp - Gm) * c * s
        A[0, 2] = -2 * la * s
        ...
        b = np.array([...])
        A = np.where(np.isnan(A), 0.0, A)
        b = np.where(np.isnan(b), 0.0, b)
        return np.asarray(A, dtype=float), np.asarray(b, dtype=float)
```

**逐行：**

- 前三行取出三个 $\Gamma$ 函数的值（把 $\gamma$、$\theta$、$\Lambda$ 代入）。
- `c`/`s` 是 $\cos\theta$/$\sin\theta$（原代码里的简写，**MATLAB 对照**：`c = cos(th); s = sin(th);`）。
- `A = np.zeros((3, 3))` —— 先建 $3\times3$ 零矩阵，再逐元素填。
  这比一次性写出复杂表达式更接近原推导的书写方式，**可读性优先**。
- `A[0, 0] = ...` —— **MATLAB 对照**：`A(1,1) = ...`，下标整体 −1。
- `b = np.array([...])` —— 三个分量的向量，一行一个。

- **最后的 NaN 清理**：
  ```python
  A = np.where(np.isnan(A), 0.0, A)
  b = np.where(np.isnan(b), 0.0, b)
  ```
  **MATLAB 对照**：`A(isnan(A)) = 0; b(isnan(b)) = 0;`
  这是最后一道保险：即使上面的 $\Gamma$ 函数漏了某个 NaN，这里也会兜住。

- `return np.asarray(A, dtype=float), np.asarray(b, dtype=float)` ——
  确保返回原生 numpy 浮点数组。
  **为什么需要**？因为 `th`/`la` 是 `np.float64` 时，
  上面某些表达式的计算结果可能变成 **0 维数组**（`np.float64` 的数组形式），
  直接赋给 `A[0,0]` 虽能自动转换，但返回前的显式转换能**保证类型稳定**，
  避免后续 `A @ x` 出现意料之外的形状。

## 8.5 矩阵偏导（全采样点版）

```python
    def _mat_vec_theta(self, th, la):
        g = self.gamma
        Gz = self._gz(th, la)
        Gzt = self._gz_th(th, la)
        ...
        N = np.size(th)
        A = np.zeros((3, 3, N))
        A[0, 0, :] = (...)
        ...
        b = np.vstack([...])
        ...
        return A, b
```

**和单点版的三个区别：**

1. **输入是数组**：`th`、`la` 是 `(N,)`，所以所有 $\Gamma$ 函数都返回 `(N,)`。

2. **输出是三维数组**：`A` 是 `(3, 3, N)`。
   **MATLAB 对照**：`A = zeros(3,3,numel(th)); A(1,1,:) = ...;`
   → Python 写 `A = np.zeros((3,3,N)); A[0,0,:] = ...`。

3. **`b` 用 `np.vstack` 拼装**：

   ```python
   b = np.vstack([
       expr1,   # 每个都是 (N,)
       expr2,
       expr3,
   ])
   ```

   得到 `(3, N)`。
   **MATLAB 对照**：`b = [ expr1 ; expr2 ; expr3 ];`（分号 = 竖直拼接）。

- `_mat_vec_lambda` 结构完全类似，只是把 `_th` 后缀换成 `_la`，
  而且**对角元以外还有几处非零**（比如 `A[0,2,:] = -2*s`），
  因为 $\partial\Lambda$ 会影响 $P$ 里所有显含 $\Lambda$ 的项。
