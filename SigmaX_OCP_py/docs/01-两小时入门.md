### 顺便：3 句话说清项目（这是**面试表述**训练，不是学习内容）

1. **问题**：给一个量子比特（含耗散），要在最短时间内把它从初态重置到目标态，
   控制手段是两个外加驱动幅度 $\lambda_x(t), \lambda_z(t)$。
2. **方法**：把时间离散成 $N$ 段，用**庞特里亚金极值原理**推出成本对控制的
   解析梯度，然后做**投影梯度下降**（可换 Adam 等加速方向），
   每步把控制投影回物理允许的盒约束内。
3. **工程价值**：把"问题"抽象成接口 `AbstractOCP`，把"算法"做成通用求解器 ——
   求解器一行不改就能解另一个完全不同的最优控制问题（`demo_example1.py` 就是证明）。

### 数据流（这张图要能在脑子里画出来）

```
控制 U (2×N)
   │  cost_gradient()
   ├─► 极坐标变换 → (theta, Lambda)
   ├─► 前向 RK4 积分 Lindblad 方程  → 状态 X (3×N)
   ├─► 终端成本 J = |p(τ)|   ← 这就是我们要最小化的东西
   ├─► 后向 RK4 积分协态方程        → 协态 Mu (3×N)
   └─► 组装梯度 G = ∂J/∂U (2×N)
             │
             ▼
      梯度下降：U ← project(U - α·G)
             │
             └──► 回到开头，直到 |grad| 足够小
```

**关键理解**：`cost_gradient()` 是唯一的"物理接口"。求解器完全不关心
`G` 是怎么算出来的 —— 这就是问题可替换的原因。

### 跑一个小实验，建立手感

```python
import sys; sys.path.insert(0, r"D:\DeepSeek\WorkSpace\SigmaX_OCP_py")
import numpy as np
from sigmax_ocp import ocp

m = ocp.QubitReset(tau=0.15, N=60, gamma=10)
tg = m.time_grid(m.N)
U = m.initial_control(tg)

J, X, Mu, G = m.cost_gradient(tg, U)
print("成本 J =", J)                      # 约 0.316
print("状态 X 形状", X.shape, " 梯度 G 形状", G.shape)

# 沿负梯度走一小步，成本应该下降
J2, _, _, _ = m.cost_gradient(tg, m.project(U - 1e-3 * G))
print("走一步后 J =", J2, " 下降？", J2 < J)
```

这个"**沿负梯度走一步成本就下降**"的验证，叫**下降方向检验**，
是验证梯度推导是否正确的标准手段。

**这才是你真正该花时间的地方** —— 五项重写核对要点：

1. **NaN 奇点处理**（`_gp / _gm / _gp_la / _gm_la`）：
   确认 `0×∞ → NaN → 置零 → 再加解析极限项` 这条路和你的推导一致。
   这里最阴险：$\textrm{spec}(0)=0$ 而 $1/\tanh(0)=\infty$，
   靠 `np.where(np.isnan(re), 0.0, re)` 兜住，再补 $(\Lambda=0)$ 的极限项。
2. **矩阵元素转录**（`_mat_vec` / `_mat_vec_theta` / `_mat_vec_lambda`）：
   逐项对照 `descriptor/main.tex`，特别是三维赋值 `A[0,0,:] = ...` 的下标有没有错位。
3. **协态终端条件**：`mu0 = -kappa * pT / nrm` ——
   系数 `kappa` 的位置和那个负号。
4. **梯度符号**：`G = -self._gradient_at(...)` 的负号
   （PMP 里 $\nabla_u J = -\partial H/\partial u$）。
5. ⭐ **$\partial\vb*{p}_0/\partial\theta$ 的几何因子** ——
   **这一项已经查出一个真错误**，请务必自己也复核一遍：

   | 数学上应为 | 规范写法 | MATLAB 版写法 | 判定 |
   |---|---|---|---|
   | $\frac{d}{d\theta}[\sin\theta(\cos\theta-2)]$ | `c²-2c-s²` | `s²-c²-2c` | ❌ **错** |
   | $\frac{d}{d\theta}[\sin\theta(\cos\theta+2)]$ | `c²+2c-s²` | `c²-s²+2c` | ✅ 巧合等价 |

   两项形式看似对称，但**只有第二项在加法交换下恰好等价**；第一项差了
   $-2(\cos^2\theta-\sin^2\theta)$。修复后纯梯度法 60 步的最终成本
   从 **1.7508e-01 降到 1.1402e-01（↓35%）**。

> ⚠️ **一个必须纠正的判断**：我最初写过"这四处只要有一项转录错了，
> `validate_suite.py` 的下降方向检验就会 FAIL" —— **这个论断是错的**。
> 第 5 项那种**局部**错误不会让下降方向检验失败：它只影响梯度的
> $\theta$ 分量，不改变下降的大方向，所以求解器照样收敛、自检照样全 PASS。
>
> **真正抓出它的是 `tests/gradient_check.py`（数值微分逐点核对）** ——
> 一个**独立于任何参考实现**的检验手段。这也正是项目里同时保留
> 两个测试脚本的原因：整体性检验查不出局部精度问题。

### 练习 B：不改求解器，加一个自己的新问题

这是整个项目**最有说服力的卖点**。写一个最小的一阶问题：

```python
import sys; sys.path.insert(0, r"D:\DeepSeek\WorkSpace\SigmaX_OCP_py")
import numpy as np
from sigmax_ocp import ocp, solver


class MyProblem(ocp.AbstractOCP):
    """min ∫ u² dt ，s.t. x' = u,  x(0)=1,  x(1)=0 —— 解析最优解是 u(t)=-1"""

    n_state = 1
    n_control = 1
    name = "my first OCP"

    def __init__(self):
        super().__init__()
        self.N = 100
        self.homotopy_name = ""

    def time_grid(self, N=None):
        return np.linspace(0.0, self.tau, N or self.N)

    def initial_state(self):
        return np.array([1.0])

    def initial_control(self, tg):
        return np.zeros((1, tg.size))

    def control_bounds(self):
        return np.array([-np.inf]), np.array([np.inf])

    def project(self, U):
        return U

    def cost_gradient(self, tg, U):
        N = tg.size
        # 状态：x' = u（u 分段常数，用 RK4 精确积分）
        X = np.zeros(N); X[0] = 1.0
        for k in range(N - 1):
            dt = tg[k + 1] - tg[k]
            X[k + 1] = X[k] + dt * U[0, k]
        # 成本 J = ∫ u² dt（终端状态自由，加一个松弛项把它往 0 拉）
        J = np.trapezoid(U[0] ** 2, tg) + 100.0 * X[-1] ** 2
        # 梯度：dJ/du = 2u + 200*X[-1]*dx[-1]/du ；dx[-1]/du_k = dt_k
        G = 2.0 * U.copy()
        dts = np.diff(tg)
        G[0, :-1] += 200.0 * X[-1] * dts
        return J, X[None, :], np.zeros((1, N)), G


p = MyProblem()
s = solver.GradientSolver(p)
s.direction = "adam"
s.max_iter = 3000
s.tol_grad = 1e-8
res = s.solve()
print("J =", res.J)
print("u 平均 =", res.U.mean(), "（解析最优解 u ≡ -1）")
```

**做这个练习的意义**：你会亲身确认 `GradientSolver` 一行没改就解了新问题。
面试时这就是"抽象设计能力"的实证。

**Q1：介绍一下这个项目？**

**Q2：梯度怎么来的？（这是你的主场，可以完整展开）**
> 终端成本是 Mayer 型 $J=|p(\tau)|$，横截条件给出协态终端值
> $\mu(\tau)=-\kappa\,p(\tau)/|p(\tau)|$。
> 协态满足后向方程 $\dot\mu=-A^\top\mu$，我把它换成 $s=-t$ 的正向积分，
> 这样能直接复用同一套 RK4。
> 拿到 $\mu$ 之后，把动力学右端 $P(\theta,\Lambda)p+p_0(\theta,\Lambda)$
> 对 $(\theta,\Lambda)$ 求偏导、用协态加权，
> 再经极坐标变换的雅可比做链式法则，就得到 $\partial J/\partial U$。
> 代价是两次积分、与时间离散点数无关，比有限差分快一个量级。

**Q2b：你 Python 用了多久？（诚实但有策略）**
> 我的主力工具链一直是 MATLAB，Python 是最近为了把工作流迁到开源生态补的。
> 这个项目里我用 numpy 手写了 RK4 积分器和解析梯度组装，没有依赖自动微分，
> 做完跟 MATLAB 版逐项对了数值，结果一致。
> 所以我能用 Python 复现我自己在 MATLAB 里做的算法；
> 工程化的细节我还在持续补。

**Q3：为什么用投影而不是罚函数？**
> 罚函数需要调罚参数，参数太小时约束不满足、太大时数值病态；
> 投影法每步把控制直接裁剪回盒约束内，无参数、数值更稳。
> 我在原理文档里两种都讨论了，实现选了投影。

**Q4：怎么验证你的实现是对的？**

**Q5：Adam 为什么比纯梯度快？**
> 它对梯度做了一阶矩和二阶矩的指数滑动平均，相当于给每个控制分量
> 自适应学习率，且用偏差校正消除初期偏差。这个问题在初始阶段梯度
> 分布很不均匀（高原区 + 陡峭区并存），自适应步长能显著加速。

**Q6：什么是同伦延拓？为什么需要？**
> 终端成本 `|p(τ)|` 在时间窗口长时会让初始控制的梯度接近消失，
> 直接优化会卡住。延拓的做法是先从"容易的问题"（比如很短的时间窗口）
> 求一个解，然后逐步把参数推向真正的问题（拉长时间 / 提高终端权重），
> 每一步都用上一步的解做热启动。`demo_prolong.py` 演示了这条路径。

**Q7：你遇到的最大困难？**
> 原工程 `solve()` 内部用的是求解器自己的网格点数，而不是模型的，
> 这两个属性互相独立、默认值都是 100，所以只要改了 `model.N` 没同步改
> `solver.N`，就会出现"解出来的控制只有 100 个点、画图却按 200 个点"的
> 维度失配。MATLAB 版 `demo_example1.m` 就栽在这里。我保留了核心库与 MATLAB
> 一致的语义（这样数值才能对齐），在 demo 层显式传时间格点修掉了它。

### 数组与下标

| MATLAB | Python / numpy | 坑 |
|---|---|---|
| `a(1)` | `a[0]` | **1-based → 0-based**，最易错 |
| `a(end)` | `a[-1]` | — |

### 循环

| MATLAB | Python |
|---|---|
| `for k = 1:N` | `for k in range(N)` |
| `for k = 1:N-1` | `for k in range(N-1)` |
| `for k = N:-1:2` | `for k in range(N-1, 0, -1)` |

> **后向循环是重写最容易翻车的地方**。`for k = N:-1:2` 里 `k` 取
> `N, N-1, ..., 2`，对应的 Python 0-based 是 `N-1, ..., 1`，
> 所以写成 `range(N-1, 0, -1)`，而循环体里原来的 `X(k-1)` 要写成 `X[k-1]`。

## 附：这个项目里最值得学的 3 个 Python 技巧

1. **抽象基类做"可替换问题"的契约**（`abstract_ocp.py`）
   `abc.ABC` + `@abstractmethod` 让"没实现接口"在**实例化时**就报错，
   而不是运行到一半才崩。这是把 MATLAB 的 `properties (Abstract)` 正确翻译过来的关键。

2. **`@dataclass` 替代 MATLAB 的 struct**
   `History` / `SolveResult` / `ContinuationStep` 都是 dataclass，
   字段名与 MATLAB 保持一致（`res.hist.J`），既省样板代码又保留熟悉感。

3. **`for ... else` 做"是否跑满循环"的判定**
   `GradientSolver.solve()` 用它判断"到底是因为收敛 break 了，
   还是迭代次数用完了"，比 MATLAB 的 `if iter == maxIter` 更准确。
   这是 Python 独有、很优雅的一个语法。
