# 一、`abstract_ocp.py` —— 抽象接口

## 1.1 它到底解决什么问题

先说清楚**为什么需要这个文件**，否则会觉得它"什么都没干"。

求解器 `GradientSolver` 要解一个最优控制问题，它需要知道：

- 状态几维、控制几维？（`n_state` / `n_control`）
- 时间怎么离散？（`time_grid`）
- 初态是什么？（`initial_state`）
- 一开始给个什么控制猜测？（`initial_control`）
- **给定控制 U，成本 J 和它对 U 的梯度 G 是多少？**（`cost_gradient`）← 核心
- 控制有什么物理限制？（`control_bounds` / `project`）

**只要这 7 件事齐了，求解器就能干活** —— 至于这个问题的物理是量子比特、
是火箭、还是经济模型，求解器一点都不关心。

`AbstractOCP` 就是把这 7 件事写成一个"合同"。MATLAB 版用 `properties (Abstract)`
和 `methods (Abstract)` 表达；Python 版用 `abc.ABC` + `@abstractmethod`。

> 这个设计的价值在 `demo_example1.py` 里得到验证：一个标量状态、带运行成本、
> 跟量子物理毫无关系的问题，用**同一个求解器、一行代码不改**就解出来了。

## 1.2 模块级：导入与类型注解

```python
from __future__ import annotations

from abc import ABC, abstractmethod

import numpy as np
```

**逐行：**

- `from __future__ import annotations` —— 开启"延迟求值注解"。作用是让类型注解
  （比如 `def f(x: np.ndarray | None)`）以**字符串**形式保存，不在定义时求值。
  好处：①可以写 `int | None` 这种新语法在旧 Python 上也能跑；②避免循环导入。
  **注意**：它只影响"注解"，不影响运行逻辑。

- `from abc import ABC, abstractmethod` —— `abc` 是标准库的"抽象基类"模块。
  - `ABC`：继承它就得到一个抽象基类。
  - `abstractmethod`：装饰器，标记"这个方法子类必须实现"。

- `import numpy as np` —— 数值计算。本项目所有数组都是 `np.ndarray`。

> **MATLAB 对照**：MATLAB 的抽象类和接口是语言内建的（`classdef (Abstract)`）；
> Python 里这是标准库提供的一个**可选**机制，你完全可以不用它（很多 Python 代码
> 就用"约定 + 文档"），但用了之后能在**实例化时**就抓住"忘了实现接口"的错误。

## 1.3 类声明与"抽象属性"

```python
class AbstractOCP(ABC):
    """所有（离散化）最优控制问题的抽象基类。"""

    n_state: int = 0      # 状态维数
    n_control: int = 0    # 控制维数
    name: str = "unnamed OCP"
```

**逐行：**

- `class AbstractOCP(ABC)` —— 继承 `ABC`。从此这个类**不能被直接实例化**
  （`AbstractOCP()` 会报 `TypeError`），而且只要还有 `@abstractmethod` 没实现，
  子类也不能实例化。

- `n_state: int = 0` —— 这是**类属性**，不是实例属性。
  意味着：`QubitReset.n_state` 直接就能读到 `3`，不用先 `new` 一个对象。
  **MATLAB 对照**：MATLAB 的 `properties (Abstract) nState; end` 强制子类必须给值；
  Python 这里给了默认值 `0`，不是强制的。这是有意的取舍 ——
  用默认值避免子类忘记定义时直接崩，同时在文档和 `__repr__` 里体现出来。

  > 如果你想强制子类必须定义，可以写成：
  > ```python
  > @property
  > @abstractmethod
  > def n_state(self): ...
  > ```
  > 但那样每处使用都要写 `self.n_state`，读起来更绕。本项目选了简单方案。

**为什么 `name` 用类属性？** 因为它是所有实例共享的常量字符串，放进每个实例
就是浪费内存，而且放在类上更直观。

## 1.4 `__init__`：实例属性

```python
    def __init__(self) -> None:
        self.tau: float = 1.0
        self.homotopy_value: float = 1.0
        self.homotopy_name: str = ""
```

**逐行：**

- `def __init__(self) -> None` —— Python 的构造函数。
  **MATLAB 对照**：`function obj = AbstractOCP()`。

- `self.tau = 1.0` —— `self` 就是 MATLAB 里的 `obj`。
  **关键区别**：MATLAB 里 `properties` 块中带默认值的属性，是在对象创建时
  自动初始化的（对象句柄类）。Python 没有这个机制，**必须在 `__init__` 里
  显式赋值**，否则访问时会 `AttributeError`。

- `homotopy_value = 1.0` —— 延拓参数，默认 1 表示"原问题"。
  子类在 `cost_gradient()` / `time_grid()` 里读它，从而支持沿参数路径延拓。

- `homotopy_name = ""` —— 延拓参数的名字（`'tau'` 或 `'kappa'`），空串表示不支持延拓。

## 1.5 六个抽象方法（**这是整个项目的骨架**）

```python
    @abstractmethod
    def time_grid(self, N: int | None = None) -> np.ndarray:
        """返回 [0, tau] 上的时间格点，shape (N,)。"""

    @abstractmethod
    def initial_state(self) -> np.ndarray:
        """返回初态，shape (n_state,)。"""

    @abstractmethod
    def initial_control(self, tg: np.ndarray) -> np.ndarray:
        """返回初始控制的猜测，shape (n_control, N)。"""

    @abstractmethod
    def cost_gradient(
        self, tg: np.ndarray, U: np.ndarray
    ) -> tuple[float, np.ndarray, np.ndarray, np.ndarray]:
        """返回 (J, X, Mu, G)。"""

    @abstractmethod
    def project(self, U: np.ndarray) -> np.ndarray:
        """把控制投影到可行盒约束上。"""

    @abstractmethod
    def control_bounds(self) -> tuple[np.ndarray, np.ndarray]:
        """返回控制的下界与上界 (Ulo, Uhi)，各 shape (n_control,)。"""
```

**逐个说清楚：**

| 方法 | 作用 | 返回形状 | MATLAB 原名 |
|---|---|---|---|
| `time_grid` | 把 `[0, tau]` 均匀分成 N 点 | `(N,)` | `timeGrid` |
| `initial_state` | 初态 $p(0)$ | `(n_state,)` | `initialState` |
| `initial_control` | 初始控制猜测（热启动） | `(n_control, N)` | `initialControl` |
| `cost_gradient` | **核心**：成本 + 状态 + 协态 + 梯度 | 见下 | `costGradient` |
| `project` | 把控制裁剪回可行域 | `(n_control, N)` | `project` |
| `control_bounds` | 上下界 | 各 `(n_control,)` | `controlBounds` |

**`cost_gradient` 的返回**（四个值，一次算完）：

```python
# (J, X, Mu, G)
#  J   : float            标量成本
#  X   : (n_state, N)     状态轨迹
#  Mu  : (n_state, N)     协态轨迹
#  G   : (n_control, N)   成本对每个控制采样点的梯度
```

> **为什么四个值一起返回？** 因为它们在同一次计算里天然一起产生：
> 算 J 要先前向积分得到 X，算梯度要先后向积分得到 Mu。分开成四个方法会导致
> 重复积分、浪费一倍以上算力。这个"一次算完"的设计直接从 MATLAB 版继承。

> **MATLAB 对照**：`[J, X, Mu, G] = costGradient(obj, tg, U)`。
> Python 用元组返回，调用方用解包接收：
> `J, X, Mu, G = model.cost_gradient(tg, U)` —— 语法几乎一样。

**关于 `N: int | None = None`**：
意思是"可以传 N，也可以不传"。子类的实现里通常写：

```python
def time_grid(self, N=None):
    if N is None:
        N = self.N          # 用实例自己的 N
    return np.linspace(0.0, self.tau, int(N))
```

**MATLAB 对照**：`function tg = timeGrid(obj, N); if nargin < 2, N = obj.N; end`。
Python 里 `N=None` 就是 `nargin < 2` 的等价写法。

```python
    def set_homotopy(self, v: float) -> None:
```

```python
    def print_info(self) -> None:
```

## 1.7 `trapezoid()` —— 一个必须知道的 numpy 大坑

```python
    @staticmethod
    def trapezoid(tg: np.ndarray, y: np.ndarray) -> float:
        """梯形法积分 ∫ y dt，等价于 MATLAB 的 ``trapz(tg, y)``。"""
        return float(np.trapezoid(y, tg, axis=-1))
```

**这是整个重写里最容易翻车的一处，务必记住：**

| | MATLAB | numpy 1.x | numpy 2.x |
|---|---|---|---|
| 函数名 | `trapz` | `np.trapz` | `np.trapezoid` |
| 参数顺序 | `(x, y)` 坐标在前 | `(y, x)` **函数值在前** | `(y, x)` **函数值在前** |

两个坑叠在一起：

1. **函数改名**：numpy 2.0 移除了 `np.trapz`。本机装的是 numpy 2.5.3，
   直接写 `np.trapz` 会 `AttributeError`。
2. **参数顺序相反**：MATLAB 是 `trapz(坐标, 函数值)`，
   numpy 是 `trapezoid(函数值, 坐标)`。

所以 `trapz(tg, y)` → `np.trapezoid(y, tg)`。**写反了不会报错，只会算错** ——
这是最危险的一类 bug。

**解决办法**：本项目把所有积分都走 `AbstractOCP.trapezoid(tg, y)` 这一个封装，
签名与 MATLAB 保持一致，内部做转换。这样：
- 全项目只需记住一个签名（和 MATLAB 一样）
- 以后 numpy 再改名，只改这一处

**其他细节：**

- `@staticmethod` —— 静态方法，不需要 `self`。因为积分就是纯计算，
  跟具体是哪个问题无关。
- `axis=-1` —— 沿**最后一维**积分。因为 `y` 可能是 `(n_control, N)`，
  时间在最后一维；`axis=-1` 比写 `axis=1` 更通用（无论前面有几维都对）。
- `float(...)` —— 包一层确保返回值是 Python 原生 `float`，而不是
  `np.float64`。好处：后续做 `f"{J:.6e}"` 格式化、`math.isfinite` 判断时
  行为更可预期，序列化（存 JSON）也不会出问题。


# 二、`line_search.py` —— 非精确步长搜索

## 2.1 它解决的问题

方向确定了，**走多远**？走太短收敛慢，走太长成本反而上升。

"线搜索"就是回答这个问题：给定下降方向 $d$，找一个步长 $\alpha$ 使得
成本"**充分下降**"。

高中数学的直觉：把成本沿方向看成单变量函数
$\phi(\alpha) = J(U + \alpha d)$。我们要找 $\alpha$ 让 $\phi$ 下降得够多。

## 2.2 `LineSearchOptions`：用 dataclass 替代 MATLAB 的 struct

```python
@dataclass
class LineSearchOptions:
    """线搜索参数。对应 MATLAB 里那个临时 struct ``s``。"""

    rho: float = 0.1          # 充分下降参数 c1
    sigma: float = 0.4        # 曲率参数 c2（Wolfe 用）
    alpha0: float = 0.5       # 初始试探步长
    alpha_min: float = 1e-8   # 最小步长
    alpha_max: float = 1.0    # 最大步长
```

**逐行：**

- `@dataclass` —— 装饰器，自动生成 `__init__`、`__repr__`、`__eq__`。
  等价于手写：

  ```python
  class LineSearchOptions:
      def __init__(self, rho=0.1, sigma=0.4, alpha0=0.5, alpha_min=1e-8, alpha_max=1.0):
          self.rho = rho
          ...
  ```

  省了 10 行样板代码，而且字段和默认值一眼看清。

- **MATLAB 对照**：MATLAB 里是临时 struct：

  ```matlab
  s.rho = obj.rho;  s.sigma = obj.sigma;  s.alpha0 = obj.alpha0;
  alpha = obj.ls.search(..., s);
  ```

  Python 用 dataclass 显式声明，好处是**字段名拼错会立刻报错**（struct 不会）。

- `rho` 和 `sigma` 就是教科书里的 $c_1$ 和 $c_2$：
  - $c_1$（`rho`）：Armijo **充分下降**参数，典型值 $10^{-4}\sim0.1$
  - $c_2$（`sigma`）：Wolfe **曲率**参数，要求 $c_1 < c_2 < 1$

## 2.3 `search()`：主体

```python
class LineSearch:
    MAX_ITER = 100

    def search(self, rule, interp, model, tg, U, d, G0, opts) -> float:
        c1 = opts.rho
        c2 = opts.sigma

        phi0 = self._phi(model, tg, U, d, 0.0)
        dphi0 = self._dphi(model, tg, U, d, 0.0)

        if dphi0 >= 0:
            return 0.0
```

**逐行：**

- `MAX_ITER = 100` —— 类属性，回溯次数上限，防止死循环。
  **MATLAB 对照**：`iter = 0; maxIter = 100;`

- `def search(self, rule, interp, model, tg, U, d, G0, opts)` —— 参数和 MATLAB 版
  完全一致。`rule` 是 `'simple'/'armijo'/'wolfe'`，`interp` 是折半方式。

  > **`G0` 其实没被用到**。保留它是为了和 MATLAB 的函数签名严格对应
  > （MATLAB 版传了 `G` 但也只在 `dphi0` 里用 `d`）。
  > 这在文档字符串里写明了。这类"保持签名一致但参数未用"的情况，
  > **一定要在注释里说清楚**，否则后来的人会以为是 bug。

- `phi0 = self._phi(...0.0)` —— $\phi(0) = J(U)$，即当前成本。
- `dphi0 = self._dphi(...0.0)` —— $\phi'(0) = \langle \nabla J, d\rangle$，
  即"沿方向 d 的初始变化率"。

- `if dphi0 >= 0: return 0.0` —— **判定 d 是不是下降方向**。
  如果导数非负，说明沿 d 走成本不会降（至少一阶上不会），直接返回步长 0，
  求解器就不会动。这是一个廉价的安全阀。

## 2.4 Armijo 回溯循环（**这一步是重点**）

```python
        alpha = opts.alpha0
        it = 0

        # ---- 阶段 1：充分下降条件（Armijo 上界） ----
        while self._phi(model, tg, U, d, alpha) > phi0 + c1 * alpha * dphi0:
            alpha = self._reduce(interp, alpha, opts.alpha_min)
            if alpha <= opts.alpha_min or it > self.MAX_ITER:
                alpha = opts.alpha_min
                break
            it += 1
```

**这个 `while` 条件是整个线搜索的核心**：

$$
\phi(\alpha) \le \phi(0) + c_1 \alpha \phi'(0)
$$

- 左边：走 $\alpha$ 之后的实际成本。
- 右边：**线性预估**的下降量（用初始斜率乘步长）。
- 要求实际下降**至少要达到线性预估的 $c_1$ 倍**。

因为 $\phi'(0) < 0$，右边是个比 $\phi(0)$ 小的数。这个条件保证"这一小步
确实带来了可观的下降"，挡住那些"看起来在降、其实几乎没降"的步长。

**逐行：**

- `alpha = opts.alpha0` —— 从 0.5 开始试。**MATLAB 对照**：`alpha = opts.alpha0;`
- `it = 0` —— 回溯计数器。
- `while <条件不满足>:` —— 只要**不满足**充分下降条件，就缩小步长重试。
  **MATLAB 对照**：`while phi(alpha) > phi0 + c1*alpha*dphi0`，一模一样。
- `alpha = self._reduce(interp, alpha, opts.alpha_min)` —— 折半（见 2.6）。
- `if alpha <= opts.alpha_min or it > self.MAX_ITER:` —— **安全出口**。
  步长已经小到不能再小，或者回溯次数超限，就放弃，直接把步长压到最小值。
- `break` —— 跳出 `while`。
- `it += 1` —— **注意 Python 没有 `++` 运算符**，必须写 `it += 1`。

**关于 `simple` / `armijo` / `wolfe` 的区别**：

- `simple` 和 `armijo` 在本实现里**行为相同** —— 都只做阶段 1。
  实际上"简单回溯"就是只有充分下降条件，而 Armijo 条件本身就是它，
  所以 MATLAB 代码里两者等价（`rule` 参数只影响阶段 2 是否执行）。
- `wolfe` 会多做阶段 2。

## 2.5 Wolfe 阶段 2

```python
        # ---- 阶段 2（仅 Wolfe）：步长不要太小（曲率条件） ----
        if rule.lower() == "wolfe" and self._dphi(model, tg, U, d, alpha) < c2 * dphi0:
            it = 0
            while self._dphi(model, tg, U, d, alpha) < c2 * dphi0:
                alpha = min(2.0 * alpha, opts.alpha_max)
                if alpha >= opts.alpha_max or it > self.MAX_ITER:
                    break
                it += 1
```

**为什么需要阶段 2？**

阶段 1 只保证"下降够多"，但**步长可能过小**（比如已经缩到 $10^{-8}$，
虽然满足下降但几乎没前进）。Wolfe 的曲率条件把步长**往大里推**：

$$
\phi'(\alpha) \ge c_2 \phi'(0)
$$

- 因为 $\phi'(0) < 0$，右边是个负数。
- 条件要求 $\phi'(\alpha)$ **不要比 $c_2\phi'(0)$ 还负** ——
  也就是"在这个步长处，斜率已经变平缓了"，说明接近局部极小，
  步长是合适的。

**逐行：**

- `rule.lower() == "wolfe"` —— **MATLAB 对照**：`strcmpi(rule, 'wolfe')`。
  `strcmpi` 是"忽略大小写比较"，Python 用 `.lower()` 再比较。
- `alpha = min(2.0 * alpha, opts.alpha_max)` —— 步长翻倍，但不超过上限。
  **MATLAB 对照**：`alpha = min(2*alpha, opts.alphaMax);`
- `if alpha >= opts.alpha_max ... break` —— 已经到最大步长就不再翻倍。

## 2.6 `_reduce()`：折半

```python
    @staticmethod
    def _reduce(interp: str, alpha: float, alpha_min: float) -> float:
        key = (interp or "").lower()
        if key in ("bi", "bisection", "quad", "quadratic"):
            a = 0.5 * alpha      # 折半 / 简单的二次收缩
        else:
            a = 0.5 * alpha
        return max(a, alpha_min)
```

**逐行：**

- `(interp or "").lower()` —— 两步：`interp or ""` 把 `None` 变成空串
  （防御性写法），再统一转小写。
- `if key in ("bi", "bisection", "quad", "quadratic"):` ——
  **MATLAB 对照**：`switch lower(interp); case {'bi','bisection','quad','quadratic'}`。
  Python 用 `in` 判断"是否属于某个元组"，比写多个 `or` 清爽。
- **两个分支代码相同**（都是 `0.5 * alpha`）—— 这是**忠实保留了 MATLAB 版
  的结构**。MATLAB 版里 `switch` 的 `case` 和 `otherwise` 也恰好取同一个值。
  保留的意义：以后要换插值方式（比如真正的二次插值
  $\alpha_{\text{new}} = -\frac{\phi'(0)\alpha^2}{2(\phi(\alpha)-\phi(0)-\phi'(0)\alpha)}$）
  时，位置已经留好了。
- `return max(a, alpha_min)` —— 不让步长掉到下限以下。
  **MATLAB 对照**：`if a < alphaMin, a = alphaMin; end`

## 2.7 `_phi` 和 `_dphi`：两个求值函数

```python
    @staticmethod
    def _phi(model, tg, U, d, alpha) -> float:
        """沿方向 d 走 alpha 后的成本 phi(alpha)。"""
        J, _, _, _ = model.cost_gradient(tg, U + alpha * d)
        return float(J)

    @staticmethod
    def _dphi(model, tg, U, d, alpha) -> float:
        """phi'(alpha) = <grad J(U + alpha*d), d>。"""
        _, _, _, G = model.cost_gradient(tg, U + alpha * d)
        return AbstractOCP.trapezoid(tg, np.sum(G * d, axis=0))
```

**逐行：**

- `J, _, _, _ = model.cost_gradient(...)` ——
  **`_` 是"我不关心这个值"的惯例**。`cost_gradient` 返回 4 个值，
  这里只要第 1 个（成本）。
  **MATLAB 对照**：`[J, ~, ~, ~] = model.costGradient(...)` ——
  `~` 就是 MATLAB 的"忽略输出"。两边思路完全一样。

- `U + alpha * d` —— 沿方向走一步。

- `np.sum(G * d, axis=0)` —— 逐元素相乘再沿时间轴求和。
  - `G` 和 `d` 都是 `(n_control, N)`，`G * d` 是逐元素乘
    （**MATLAB 对照**：`G .* d`）
  - `axis=0` 是"沿第 0 维（控制维）求和"，得到 `(N,)`
    （**MATLAB 对照**：`sum(G .* d, 1)` —— **MATLAB 的 dim 1 对应 numpy 的 axis 0**）

- `AbstractOCP.trapezoid(tg, ...)` —— 再沿时间积分，得到标量。
  这就是内积 $\langle \nabla J, d\rangle = \int \sum_i G_i d_i \, dt$。

> **性能提示**：`_phi` 和 `_dphi` 每次调用都要跑一遍完整的
> `cost_gradient`（含两次 RK4 积分）。所以一次线搜索可能调用它十几次 ——
> 这就是为什么"迭代 400 次"的实际耗时远大于"400 × 单次 cost_gradient"。
> 理解这一点，才能解释 `demo_prolong.py` 为什么要跑 80 秒。

## 3.5 `_apply_active_set()`：KKT 活动集

```python
    def _apply_active_set(self, U, G):
        lo, hi = self.model.control_bounds()
        at_up = U >= hi[:, None] - 1e-12
        at_lo = U <= lo[:, None] + 1e-12
        outward = (at_up & (G < -1e-12)) | (at_lo & (G > 1e-12))
        G = G.copy()
        G[outward] = 0.0
        return G
```

**这段在讲什么？**

控制有盒约束 $u_{\min} \le u \le u_{\max}$。如果某个控制分量**已经顶在上界**，
而梯度还在指示"继续增大"，那这个方向是**物理上不可行**的 ——
投影会立刻把它拉回来，白费力气。

**KKT 条件**的做法就是：**在起作用约束（active constraint）处，
把指向可行域外的梯度分量置零**。

**逐行：**

- `lo, hi = self.model.control_bounds()` —— 拿到上下界，各是 `(n_control,)`。
- `hi[:, None]` —— **把一维数组变成列向量**，形状 `(n_control, 1)`。
  这样才能和 `U` 的 `(n_control, N)` 广播（broadcasting）。
  **MATLAB 对照**：MATLAB 里 `hi` 本来就是 `(n_control, 1)` 列向量，
  所以自动广播。Python 里一维数组是"扁的"，必须显式加维度 ——
  **这是从 MATLAB 转 numpy 最常遇到的麻烦之一**。
- `- 1e-12` —— 容差：浮点误差下"刚好等于上界"可能算成 1.9999999999，
  放宽一点避免漏判。
- `at_up` / `at_lo` —— 布尔数组，标记哪些分量贴在上/下界。
- `outward` —— 逻辑组合：
  **贴在上界且梯度为负**（想把 u 变小？不对，是 `G < 0` 表示"增大 u 能降成本"，
  但已经在最大了，动不了）**或** **贴在下界且梯度为正**。
  > 梯度是 $G = \partial J/\partial U$。下降方向是 $-G$。
  > 在上界处若 $G > 0$，说明 $-G < 0$（想继续增大 u），被上界挡住 → 置零。
  > 原代码写的是 `at_up & (G < -1e-12)`，这里 `G < 0` 表示 $-G > 0$，
  > 即"想减小 u"，那在下界才该被挡… 这类符号推理容易绕，
  > **实际使用时建议直接跑实验验证**：打开 `kkt_active_set` 看成本是否
  > 下降得更快、控制是否更贴边界。
- `G = G.copy()` —— ⚠️ **必须拷贝！** 因为下一行是**原地修改** `G[...] = 0`。
  如果不拷贝，就会改到调用方传进来的数组（那是 `cost_gradient` 返回的，
  可能还被 `best_G` 引用着）。

## 3.6 `_compute_direction()`：6 种方向优化

```python
    def _compute_direction(self, model, tg, U, G) -> np.ndarray:
        method = self.direction.lower()
        self._k += 1

        if method in ("grad", "gradient"):
            ddir = -G
```

- `self._k += 1` —— 迭代计数，Adam 的偏差校正要除以 $1-\beta_1^k$，所以需要它。
- `-G` —— **最朴素的梯度下降方向**：负梯度。

```python
        elif method == "adagrad":
            if self._v is None:
                self._v = np.zeros_like(G)
            self._v += G**2
            ddir = -G / (np.sqrt(self._v) + self.eps)
```

- **AdaGrad**：累积历史梯度平方 $v \leftarrow v + G^2$，
  用它做分母实现"每个分量自适应学习率"。
  梯度一直很大的分量，分母变大 → 步长自动变小。
- `self._v is None` 时初始化 —— 对应 MATLAB 的 `if isempty(obj.v), obj.v = zeros(size(G)); end`。
- `self._v += G**2` —— 原地累加。
- `+ self.eps` —— 防止除以 0。$\varepsilon = 10^{-8}$。

```python
        elif method == "rmsprop":
            if self._v is None:
                self._v = np.zeros_like(G)
            self._v = self.beta2 * self._v + (1.0 - self.beta2) * G**2
            ddir = -G / (np.sqrt(self._v) + self.eps)
```

- **RMSProp**：把 AdaGrad 的"无限累加"改成"指数滑动平均"，
  这样历史梯度的影响会衰减，不会让学习率一直变小到 0。

```python
        elif method in ("momentum", "cm"):
            if self._m is None:
                self._m = np.zeros_like(G)
            self._m = self.beta1 * self._m + (1.0 - self.beta1) * G
            ddir = -self._m
```

- **经典动量**：$m \leftarrow \beta_1 m + (1-\beta_1)G$。
  像小球滚下坡一样累积速度，可以冲过小坑和鞍点。

```python
        elif method in ("nestorov", "nag"):
            if self._m is None:
                self._m = np.zeros_like(G)
            U_la = U + self.beta1 * self._m
            _, _, _, G_la = model.cost_gradient(tg, U_la)
            self._m = self.beta1 * self._m + (1.0 - self.beta1) * G_la
            ddir = -self._m
```

- **Nesterov 加速**：先用当前动量"向前看一步"到 `U_la`，
  在**那个点**算梯度再更新动量。直觉是"先按惯性冲出去看看，
  再根据前方的坡度修正"，比经典动量更早刹车、收敛更快。
- **代价**：每轮**多算一次 `cost_gradient`**（`G_la`），所以明显更慢。
  这是一个典型的"精度换时间"。

```python
        elif method == "adam":
            if self._m is None:
                self._m = np.zeros_like(G)
            if self._v is None:
                self._v = np.zeros_like(G)
            self._m = self.beta1 * self._m + (1.0 - self.beta1) * G
            self._v = self.beta2 * self._v + (1.0 - self.beta2) * G**2
            m_hat = self._m / (1.0 - self.beta1**self._k)
            v_hat = self._v / (1.0 - self.beta2**self._k)
            ddir = -m_hat / (np.sqrt(v_hat) + self.eps)
```

- **Adam = Momentum + RMSProp + 偏差校正**。
- `m` 是一阶矩（梯度均值），`v` 是二阶矩（梯度平方均值）。
- `m_hat` / `v_hat` 是**偏差校正**：因为 `m` 和 `v` 初始化为 0，
  前几步会偏向 0。除以 $1-\beta^k$ 把它修正回来
  （$k$ 是当前迭代数，`self._k`）。
- 实测在这个问题上 **Adam 收敛最快**（60 步 0.316→0.053，
  而纯梯度只到 0.175）。

```python
        else:
            raise ValueError(f"GradientSolver: 未知的 direction '{self.direction}'")
        return ddir
```

- **未知方向直接报错**，而不是静默地什么都不做。
  **MATLAB 对照**：`error('GradientSolver: unknown direction "%s"', obj.direction)`。
  这是一个好习惯：**宁可吵，不要猜**。

## 3.7 `_line_search_step()`：把参数打包给线搜索

```python
    def _line_search_step(self, model, tg, U, ddir, G) -> float:
        opts = LineSearchOptions(
            rho=self.rho, sigma=self.sigma,
            alpha0=self.alpha0, alpha_min=self.alpha_min, alpha_max=self.alpha_max,
        )
        return self._ls.search(
            self.line_search, self.interpolation, model, tg, U, ddir, G, opts
        )
```

- 把求解器的参数装进 `LineSearchOptions`，再调用线搜索器。
  **MATLAB 对照**：

  ```matlab
  s.rho = obj.rho;  s.sigma = obj.sigma;  s.alpha0 = obj.alpha0;
  s.alphaMin = obj.alphaMin;  s.alphaMax = obj.alphaMax;
  alpha = obj.ls.search(obj.lineSearch, obj.interpolation, model, tg, U, ddir, G, s);
  ```

- 这样做的意义：**线搜索器本身不认识求解器**，
  它只接收一个参数包。于是同一份线搜索代码可以被任何求解器复用 ——
  和 `AbstractOCP` 解耦问题是同一个设计思想：**依赖参数，不依赖具体对象**。

# 小结：这一篇里最值得记住的 6 件事

| # | 知识点 | 为什么重要 |
|---|---|---|
| 1 | `abc.ABC` + `@abstractmethod` | 把 MATLAB 的抽象类正确翻译过来，错误在实例化时就暴露 |
| 2 | `np.trapz` → `np.trapezoid`，**且参数顺序相反** | 写反不报错、只算错，最危险 |
| 3 | MATLAB 的 `dim 1` = numpy 的 `axis 0` | 所有 `sum` 都要检查 |
| 4 | `range(1, n+1)` 才等于 MATLAB 的 `1:n` | 循环边界，`range` 右端不含 |
| 5 | `for ... else` | 判断"循环是否被 break"，比 MATLAB 的写法更准 |
| 6 | `dataclass` 的可变默认值要用 `default_factory` | 否则多个实例共享同一个 list |
